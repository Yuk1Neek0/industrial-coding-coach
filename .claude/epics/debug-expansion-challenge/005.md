# Task: Challenge List Page — Page Spec + Claude Design prompt

## Description

Author the Page Spec and the Claude Design prompt for the Challenge List
Page — the UI hand-off gate for the M9 list view. Per ADR 0007, no UI
is generated before a Page Spec and a Claude Design prompt exist. The
page lists, for the current imported repo's snapshot, every applicable
challenge (lazy per type per R2), each entry naming the target
file(s) / module(s) from the M6 project map; types that do not apply
are omitted (R1 / FR-2). The user's latest outcome per challenge is
surfaced as the entry's current status.

## Technical Details

Per ADR 0007, every new page in M9 goes through the Claude Design
round-trip: Page Spec under `docs/design/` → prompt under
`docs/design/ui-prompts/` → Claude Design draft → integration notes
under `docs/design/ui-integration-notes/` at integration time
(task 009). v0 is **not** used in M9 (epic Architecture Decisions).

Follow the `docs/design/` page-spec and `ui-prompts/` conventions
established by M4 / M5 / M6 / M8 (see
`.claude/epics/archived/diff-review/115.md` and
`.claude/epics/archived/project-logic-mapper/107.md`). No code in this
task — it is the design hand-off gate that contributes to unblocking
task 009.

The spec must make the lazy-per-type behavior (R2) visible to the
integration agent: opening a category triggers generation only on
first open; subsequent opens read the cached row from `challenges`.
The page itself does **not** trigger generation on render of the list
view — generation is triggered on category open / Detail Page
navigation per R2 (clarified in task 003).
