# Task: Completion Review UI — Page Spec + Claude Design prompt

## Description

Author the Page Spec and the Claude Design prompt for the Completion
Review UI — the surface that renders the grading-call output: 0–100
numeric score, per-criterion result, weak-area breakdown matching
M8's shape (R4), and a short feedback paragraph (US-4 / FR-5). Per
ADR 0007, no UI is generated before a Page Spec and a Claude Design
prompt exist. Every file/module reference shown in the Completion
Review must resolve to a real path in the M6 project map (FR-6).

## Acceptance Criteria
- [ ] Page Spec at `docs/design/completion-review-ui.md` covering the
      Completion Review UI's host route (resolved by task 006: inline
      on the Challenge Detail Page or its own sub-route under
      `apps/web/app/repos/[owner]/[repo]/challenges/[challengeId]/...`),
      purpose, data inputs (a `challenge_attempts` row with grading
      result from task 001's data-access layer), and data outputs (no
      writes from this view).
- [ ] The spec specifies the four primary regions: **0–100 numeric
      score**, **per-criterion result list** (each criterion: passed
      / not passed + brief note), **weak-area breakdown** matching
      M8's shape (R4 / FR-5), and a **short feedback paragraph**
      (FR-5).
- [ ] The spec states the **pass threshold and weak-area schema are
      shared with M8** (R4) — render them with the same labels and
      grouping as M8's Score / Weak Area UI so the product surfaces
      one comprehension-grading pattern across M8 and M9.
- [ ] The spec states that **every file/module reference shown in the
      Completion Review resolves to a real path in the M6 project
      map** (R8 / FR-6) and that the page renders only outputs that
      have passed the task-002 integrity check.
- [ ] The spec captures the "retry this challenge" affordance (US-6):
      after seeing feedback, the user can return to the Debug
      Walkthrough UI (task 007) to submit a new attempt; both attempts
      and grades persist.
- [ ] The spec is explicit that **the page does not claim "this
      passes"** (FR-7): scoring is over the user's explanation only,
      not over executed code.
- [ ] Claude Design prompt under
      `docs/design/ui-prompts/completion-review-ui.md` references the
      typed grading shape (FR-5) and the M8 weak-area schema so
      integration in task 009 is unambiguous.
- [ ] **Claude Design (ADR 0007) is the UI generation tool — v0 is not
      used.**

## Technical Details

Per ADR 0007, every new page in M9 goes through the Claude Design
round-trip: Page Spec under `docs/design/` → prompt under
`docs/design/ui-prompts/` → Claude Design draft → integration notes
under `docs/design/ui-integration-notes/` at integration time
(task 009). v0 is **not** used in M9 (epic Architecture Decisions).

R4 — "0–100 score plus weak-area breakdown matching M8" — is the
single most important design constraint here: the Completion Review
UI should be visually and structurally consistent with M8's Score /
Weak Area UI (`.claude/epics/archived/diff-review/115.md`) so that a
user who has used M8 recognises the grading shape immediately.

R5 (prior attempts inline collapsible) is owned by task 006's
Detail Page spec — this spec does **not** redefine it; it only
declares that the latest grading result is what the Completion
Review renders.

Follow the page-spec / prompt conventions used by M4 / M5 / M6 / M8
(see `.claude/epics/archived/diff-review/115.md`). No code in this
task.
