# Task: Debug Walkthrough UI — Page Spec + Claude Design prompt

## Description

Author the Page Spec and the Claude Design prompt for the Debug
Walkthrough UI — the surface where the user submits a free-text
explanation of which files they would change and why, optionally with
small per-file code snippets keyed to specific paths from the M6
project map (US-3 / FR-4). Per ADR 0007, no UI is generated before a
Page Spec and a Claude Design prompt exist. The Walkthrough is the
**answer-entry** surface; grading is shown afterwards by the
Completion Review UI (task 008).

## Acceptance Criteria
- [ ] Page Spec at `docs/design/debug-walkthrough-ui.md` covering the
      Debug Walkthrough UI's host route (resolved by task 006: inline
      on the Challenge Detail Page or its own sub-route under
      `apps/web/app/repos/[owner]/[repo]/challenges/[challengeId]/...`),
      purpose, data inputs (active challenge from task 001), and data
      outputs (a `challenge_attempts` row written via task 001's
      data-access layer).
- [ ] The spec specifies a **free-text explanation field** as the
      primary input (FR-4) and **optional per-file code snippets**
      keyed to specific paths drawn from the M6 project map for the
      snapshot (FR-4 / R8 / US-3). The file-path picker is limited to
      M6-named paths — no free-typed paths.
- [ ] The spec captures, on submit, the file paths the user said they
      would change (FR-4) and persists the attempt server-side via
      task 001's data-access layer; the attempt is retrievable
      (US-3).
- [ ] The spec states that **grading is over the user's explanation
      only** — optional snippets are illustrative context and **not
      scored for style, naming, or plausibility** (R3 / FR-7). This
      framing must reach the user (e.g., an inline note next to the
      snippet field) so the user is not misled into thinking snippet
      quality affects the score.
- [ ] The spec specifies the user-facing scope hint: the active
      challenge's in-scope and out-of-scope file/module sets are
      visible while the user is answering (R8).
- [ ] Claude Design prompt under
      `docs/design/ui-prompts/debug-walkthrough-ui.md` references the
      typed challenge shape (FR-3) and the typed attempt shape (FR-4)
      so integration in task 009 is unambiguous.
- [ ] **Claude Design (ADR 0007) is the UI generation tool — v0 is not
      used.**

## Technical Details

Per ADR 0007, every new page in M9 goes through the Claude Design
round-trip: Page Spec under `docs/design/` → prompt under
`docs/design/ui-prompts/` → Claude Design draft → integration notes
under `docs/design/ui-integration-notes/` at integration time
(task 009). v0 is **not** used in M9 (epic Architecture Decisions).

The Walkthrough is the **answer entry** surface, not the grading
surface — grading is rendered by the Completion Review UI (task 008).
Keep the two specs separate so the answer-entry surface and the
grading surface evolve independently.

R3 / FR-7 is a normative boundary: snippets are illustrative and
**not graded**. Surface that explicitly to the user so they don't
spend effort polishing snippet quality expecting it to move the
score.

Follow the page-spec / prompt conventions used by M4 / M5 / M6 / M8
(see `.claude/epics/archived/diff-review/115.md`). No code in this
task.
