# Task: Traceability graph + detection + degradation

## Description

Create `packages/db/src/ccpm/graph.ts` — a pure builder that turns the parsed
artifacts (002) into a typed `CcpmTraceabilityMap` (PRD → epic → task nodes,
issue/PR leaf slots), **or** a `NoCcpmWorkflow` detection state when no CCPM
artifacts are present. Resolves edges from real fields: epic→PRD via `prd:`,
PRD→epic by name, task→epic by directory, task→issue via `github:`. Deterministic
ordering throughout. This is the structural backbone the teaching layer (006),
data-access (007), and Page Spec (008) all build on.

## Acceptance Criteria
- [ ] Given parsed PRDs/epics/tasks, produces a typed map with PRD, epic, and
      task nodes and the resolved parent/child edges.
- [ ] Epic→PRD resolves 100% via the epic's `prd:` field; PRD-without-epic and
      epic-without-PRD are represented (not dropped, not errors).
- [ ] Task→issue link slot populated from `github:`; a task with no `github:`
      is flagged `synced: false` (kept in the map, US-1).
- [ ] Detection: when no PRD/epic/task artifacts exist, returns a typed
      `NoCcpmWorkflow` state reporting WHAT was searched (`.claude/prds/`,
      `.claude/epics/`) — never throws or returns an empty map ambiguously.
- [ ] Deterministic ordering (e.g. PRDs by name, tasks by `taskRef`) so output
      is stable across runs.
- [ ] Handles this repo's real shapes: archived epics, missing `github:`,
      PRD-without-epic — covered by a fixture test.
- [ ] Pure, no I/O; exported for direct unit testing with passing Vitest.

## Technical Details
- New file only: `packages/db/src/ccpm/graph.ts` (+ `graph.test.ts`).
- Consume the parser output types from 002; do not re-parse.
- The issue/PR leaf is a *slot* the linking task (005) fills at import — graph
  builder only records the `github:` ref + `synced` flag, it does NOT fetch.
- Model the result as a discriminated union (`{ kind: "map", ... } | { kind:
  "absent", searched: [...] }`) consistent with the M11/M7 result-value style.
