# Task: Live issue/PR linking at import (local-first)

## Description

Create `packages/db/src/ccpm/linking.ts` — at import time, for each parsed task
carrying a `github:` issue ref, resolve the issue state and its closing PR using
M11's existing GitHub client (`issues.ts` `fetchIssue`, `pull-requests.ts`), and
persist the annotation (001's storage). The map view then reads links locally and
makes **zero** network calls (ADR 0009). Reuses M11's `GitHubResult` boundary
model; a link failure becomes a per-task "couldn't link status" annotation, never
a fatal import error.

## Acceptance Criteria
- [ ] `resolveCcpmLinks(owner, repo, ref?)` reads parsed tasks from the snapshot,
      and for each `github:` issue ref resolves issue state (open/closed) + the
      closing PR identity/url, persisting via 001's storage.
- [ ] All resolution happens at import; the map data-access (007) performs NO
      network calls — asserted by a test that the read path never invokes the
      client.
- [ ] The four M11 boundary errors + generic fallback degrade to a stored
      per-task "link failed" annotation with a beginner-safe reason (no raw HTTP
      codes); the rest of the links + the map still persist.
- [ ] Tasks with no `github:` ref are skipped cleanly (no annotation, no error).
- [ ] Re-import refreshes link annotations in place (no orphan/duplicate rows).
- [ ] Vitest with a mocked GitHub client covers: success, closed-with-PR,
      unsynced task, and each boundary error.

## Technical Details
- New file: `packages/db/src/ccpm/linking.ts` (+ `linking.test.ts`).
- Reuse `fetchIssue` / `listIssues` (`issues.ts`) and the PR model from
  `pull-requests.ts`; inject a mocked client like M11/M7 tests do.
- IMPORTANT: do NOT edit `import.ts` (keeps parallelism with 003). Linking is a
  separate pass invoked after the snapshot exists; the wiring into the import
  flow is owned by the data-access layer (007) / a thin orchestration wrapper, so
  M11's import stays pure and 003↔005 don't conflict.
- Persist with the same transaction discipline as M11's import (replace on
  re-import).

## Dependencies

  in snapshot).
