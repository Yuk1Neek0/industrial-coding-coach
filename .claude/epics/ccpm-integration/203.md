# Task: Typed data-access layer (getDeliveryMap)

## Description

Create `packages/db/src/ccpm/index.ts` — the typed read API the UI consumes,
composing the parser (002) → graph (004) → teaching (006) → persisted links (005)
into a single `getDeliveryMap(owner, repo, ref?)` result, **or** the
`NoCcpmWorkflow` degradation state. Reads strictly from the local snapshot
(`repo_files` + 001's tables) — never the live filesystem, never the network
(ADR 0009). Also owns the thin orchestration that invokes 005's linking as part
of the import flow so links are resolved at import, not at view.

## Acceptance Criteria
- [ ] `getDeliveryMap(owner, repo, ref?)` returns a typed result: a full
      traceability map (nodes + edges + teaching + persisted issue/PR links) or
      the `NoCcpmWorkflow` state — for both a CCPM repo and a non-CCPM snapshot.
- [ ] The read path performs ZERO network calls (links come from 001's storage) —
      asserted by test.
- [ ] Import-time link resolution (005) is wired here (or in a thin wrapper this
      module owns) so the view is always offline; `import.ts` is not modified.
- [ ] Public exports added to `packages/db/src/index.ts` following the existing
      module-export pattern.
- [ ] Vitest covers: CCPM repo (map populated, links present), non-CCPM snapshot
      (degradation), and a snapshot with unsynced tasks.

## Technical Details
- New file: `packages/db/src/ccpm/index.ts` (+ `index.test.ts`); export from the
  package root `index.ts`.
- Compose existing modules; this layer adds NO new parsing/graph logic — it
  orchestrates and shapes the result for the Server Action.
- Mirror the data-access ergonomics of `github/repos.ts` and the M7/learning-
  memories data-access (injectable `db`, `ref?` optional → latest snapshot).
