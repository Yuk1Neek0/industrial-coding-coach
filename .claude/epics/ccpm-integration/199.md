# Task: Snapshot coverage for .claude CCPM artifacts

## Description

Extend key-file selection so the import pipeline captures the **contents** of
`.claude/prds/**` and `.claude/epics/**` (incl. `archived/`) into `repo_files`.
Today `classifyKeyFile` ignores `.claude/`, so `repo_files` never holds CCPM
artifact bodies — which means even M7's `listCcpmTasks` returns empty on a real
import. This task closes that latent gap (FR-8) with no new fetch infrastructure:
the existing `selectKeyFiles` → `importRepository` → `repo_files` path does the
work once these paths classify.

## Acceptance Criteria
- [ ] `classifyKeyFile` returns new categories for CCPM artifacts:
      `ccpm-prd` (`.claude/prds/*.md`), `ccpm-epic` (`.claude/epics/<e>/epic.md`),
      `ccpm-task` (`.claude/epics/<e>/<N>.md`), including the `archived/` subtree.
- [ ] Non-artifact `.claude/` files (e.g. `github-mapping.md`, `*-analysis.md`,
      `execution-status.md`, `skills/**`, `settings*.json`) are NOT captured —
      only PRDs/epics/tasks.
- [ ] `KeyFileCategory` type + exports updated; `repo_files.category` now carries
      the new values for downstream branching.
- [ ] Importing a CCPM repo results in `.claude/prds/**` and `.claude/epics/**`
      (incl. archived) appearing in `repo_files` with bodies — verified by an
      `import.test.ts` / `key-files.test.ts` case with a CCPM-shaped tree.
- [ ] Size/rate budget respected: CCPM markdown is small and stays under
      `MAX_KEY_FILE_BYTES`; no change to the selective-fetch model (ADR 0009).
- [ ] M7's `listCcpmTasks` now returns real tasks against such a snapshot
      (regression-style assertion welcome).

## Technical Details
- Edit `packages/db/src/github/key-files.ts` (classifier + category type) and, if
  needed, `import.ts` only for the category typing. These files are NOT touched by
  any other Wave-1 task → parallel-safe.
- Add the artifact path patterns alongside the existing `EXACT_NAME_CATEGORIES` /
  `BUILD_CONFIG_PATTERNS` structure; keep `classifyKeyFile` pure and total.
- Do not import the new `ccpm/parse.ts` here — classification is path-based; the
  parser consumes the captured contents later.
