# Task: Integrate the Delivery page into apps/web

## Description

Build `apps/web/app/delivery/[owner]/` — a Server Component shell + Client island
that renders the delivery traceability map (or the degradation state) by calling a
Server Action over the data-access layer (007), implementing the Page Spec (008).
Mirrors the M11 `/import` and M6 `/map/[owner]` Server-Component-+-island pattern.
Final integration task — sequential, after backend + spec are done.

## Acceptance Criteria
- [ ] `/delivery/[owner]` route renders the traceability map for an imported CCPM
      repo: PRD → epic → task → issue/PR, with per-node teaching from 006.
- [ ] A non-CCPM repo renders the "no spec-driven workflow detected" educational
      state (no error, no empty crash) with a working link to the M2 Golden Path.
- [ ] Unsynced tasks render as "not synced"; link failures render the beginner-
      safe annotation — no raw HTTP codes / stack traces.
- [ ] Data flows via a Server Action over 007's `getDeliveryMap`; no client-side
      network to GitHub; no live filesystem reads.
- [ ] Discoverable: linked from the relevant existing surface (e.g. the repo/owner
      navigation used by `/map`, `/stack`, `/portfolio`).
- [ ] `pnpm lint`, `pnpm build`, `pnpm typecheck` pass; CI green on the PR.
