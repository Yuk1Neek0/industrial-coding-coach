# Task: GitHub-access ADR + snapshot schema + migration

## Description

Settle and record the GitHub-access decisions in a new ADR, then define the
local snapshot storage schema + migration. This is foundational — the API
client, import module, and data-access layer all depend on the storage shape
and the access decisions made here.

## Acceptance Criteria
- [ ] A new ADR under `docs/decisions/` records: authentication (token via
      `.env`), rate-limit handling strategy, and snapshot storage choice
      (SQLite per ADR 0006 vs. file cache).
- [ ] A snapshot schema is defined — repo metadata, file tree, key-file
      contents — keyed by `owner/repo` + ref.
- [ ] A Drizzle migration (or chosen storage equivalent) is generated and
      applies cleanly to a fresh DB.
- [ ] `.env.example` documents the GitHub token variable (placeholder only).

## Technical Details

- Default leaning: store snapshots in the existing catalog SQLite DB (ADR 0006);
  the ADR confirms or overrides this.
- Mirror the M2 schema/migration conventions in `packages/db`.
- Read-only access scope only.

## Dependencies

- M0 foundation; ADR 0006.
