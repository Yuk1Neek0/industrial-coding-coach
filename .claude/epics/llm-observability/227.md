# Task: Integrate the Observability page into apps/web

## Description

Build `apps/web/app/observability/[owner]/[repo]/` — a Server Component shell
that renders the observability page (Part A traces/evals/cost + Part B story +
teaching, or the degradation state) by reading the task-7 data-access layer,
implementing the Page Spec (task 8). Mirrors the M12 `/delivery/[owner]/[repo]`
Server-Component pattern. Final integration task — sequential.

## Acceptance Criteria
- [ ] `/observability/[owner]/[repo]` renders Part A (traces list + per-call
      aggregate cards: count, eval pass-rate, est. cost, avg latency) and Part B
      (the repo observability story + teaching) for an imported repo.
- [ ] A non-LLM repo renders the Part-B `absent` educational state; a repo with no
      traces yet renders the Part-A "no calls traced yet" empty state — neither is
      an error.
- [ ] Estimated cost is labelled an estimate; no raw HTTP codes / stack traces.
- [ ] Data flows via a `lib/observability.ts` facade over task-7 `getObservability`;
      no client-side network; no live FS reads (mirrors `lib/delivery.ts`).
- [ ] Discoverable: an "Observability" entry in the primary nav (mirroring the M12
      Delivery entry).
- [ ] `loading` / `not-found` / `error` routes; `pnpm --filter web typecheck`,
      `lint`, `build` pass; a `lib/observability.test.ts` covers the facade.

## Technical Details
- New route `apps/web/app/observability/[owner]/[repo]/` + `_components/` + a
  `lib/observability.ts` facade — follow the M12 `/delivery` files exactly
  (Server Component, `force-dynamic`, page-local chrome, `lib/*` facade pattern).
- Consume the Page Spec (8) + the Claude Design draft. Use `packages/ui` +the
  existing CSS design-system classes; beginner-first copy.
- Only task touching `apps/web` in this epic → no in-epic UI conflict.

## Dependencies
- 7 (data-access), 8 (Page Spec + design draft).
