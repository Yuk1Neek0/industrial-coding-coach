# Task: Part-B repo observability teaching

## Description

Create `packages/db/src/observability/teaching.ts` — a pure, deterministic
teaching layer over the Part-B analyzer output (task 3), parameterized by the
real findings: what observability the repo has, what a production setup would add
(tracing, cost, evals), and how to answer "how would you monitor and evaluate
this?" in an interview. Includes the educational copy for the `absent` state.
Mirrors the M12 teaching pattern (no LLM).

## Acceptance Criteria
- [ ] `buildObservabilityTeaching(story)` returns beginner-first explanations
      parameterized by the analyzer's real findings (named SDK(s), call-site
      count, whether tracing/evals tooling was detected) — not generic boilerplate.
- [ ] Covers the three concepts a junior dev should speak to: tracing (prompts/
      tokens/cost/latency), failures, and evals — each tied to what the repo has
      or lacks.
- [ ] Names the professional/interview value ("how would you monitor and evaluate
      this in production?").
- [ ] The `absent` (no LLM app detected) case returns a clear, calm educational
      explainer — not an error.
- [ ] No raw errors/jargon-without-definition; pure + deterministic; no SDK call.
- [ ] Vitest covers a detected story (asserts real findings appear) and the absent case.

## Technical Details
- New file only: `observability/teaching.ts` (+ `teaching.test.ts`). Input is the
  task-3 story type; output is a typed explanation structure the UI renders.
- Keep copy in one small templating table (reviewable/testable); no Anthropic SDK import.
