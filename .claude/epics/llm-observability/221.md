# Task: Repo observability analyzer (Part B detection)

## Description

Create `packages/db/src/observability/detect.ts` — a pure analyzer over an
imported snapshot's `repo_files` that detects whether the repo is an LLM app and
produces a typed **observability story**: detected AI SDKs, model-call sites,
prompt assets, and any existing observability/eval tooling. Mirrors the M12
graph's pure-analyze pattern (AD-5).

## Acceptance Criteria
- [ ] `analyzeObservability(files)` returns a discriminated result: a typed story
      (`{ kind: "llm-app", sdks, callSites, promptAssets, existingTooling }`) or a
      `{ kind: "absent" }` detection state when no LLM signals are found.
- [ ] Detects AI SDK signals deterministically: `@anthropic-ai/sdk` / `anthropic`,
      `openai`, and common others, from manifest deps and import statements in
      captured files.
- [ ] Detects existing observability/eval tooling signals (e.g. `langfuse`,
      `openllmetry`/`traceloop`, an `evals/` dir) and prompt assets (e.g.
      `*.prompt`, a `prompts/` dir) when present in the snapshot.
- [ ] Tolerant of partial snapshots (key-file selection may not capture every
      source file) — reports what it found, never throws; absence is a clean state.
- [ ] Pure, no I/O; exported for direct unit testing. Vitest covers: an LLM-app
      fixture, a tooling-present fixture, and a non-LLM fixture → `absent`.

## Technical Details
- New file only: `observability/detect.ts` (+ `detect.test.ts`). Input is the
  `RepoFile[]` shape (path + content + category) — the analyzer is pure over that.
- Signals come from manifest (`package.json` deps), import lines, and path
  patterns. Note the snapshot only captures key files + (from M12) `.claude/**`;
  detection is best-effort over what's present and says so.
- Discriminated-union result mirrors the M11/M12 result-value style.
