# Task: Observability schema + Drizzle migration

## Description

Add the local-first, Langfuse-shaped storage for LLM observability to
`packages/db/src/schema.ts` + a Drizzle migration: `llm_traces` (one row per
logical bounded call) and `llm_evals` (zero-or-more per trace). The recording
decorator (task 4) writes these; the data-access layer (task 7) reads them.

## Acceptance Criteria
- [ ] `llm_traces` stores: a stable call `name` (e.g. `m10.generate-qa`), optional
      `snapshotId` (FK → `repo_snapshots.id`, cascade), `model`, aggregate
      input/output/cache token counts, `estimatedCostUsd`, `latencyMs`, a typed
      `outcome` (`success` | failure kind), `startedAt`, and a JSON `observations`
      array (per-`complete()`-turn breakdown).
- [ ] `llm_evals` stores: `traceId` (FK → `llm_traces.id`, cascade), `check`
      name, `passed` boolean, and a nullable `reason`.
- [ ] A Drizzle migration (`0011`) is generated against current `main` and
      applies cleanly to a fresh in-memory DB.
- [ ] Exported `$inferSelect`/`$inferInsert` types for both tables, following the
      existing schema pattern; an index on `llm_traces.snapshotId` for per-repo reads.
- [ ] Schema-shape unit test (mirrors `ccpm-schema.test.ts`): insert/read a trace
      + eval, the FK cascade, and the snapshot index.

## Technical Details
- Edit only `schema.ts` (+ generated migration + a new `*-schema.test.ts`). No
  other task touches these → Wave-1 parallel-safe.
- Langfuse-shaped: trace / observation (JSON for MVP) / score(=eval). The export
  seam (AD-6) maps `llm_traces` → trace, `observations` → observations, `llm_evals`
  → scores. Keep `category`/enum-ish columns as free `text` (no enum migration).
- `snapshotId` is nullable so a non-snapshot call could still be traced; M7/M9/M10
  are all snapshot-scoped.
