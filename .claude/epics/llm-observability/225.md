# Task: Typed observability data-access layer

## Description

Create `packages/db/src/observability/index.ts` — the typed read the UI consumes:
`getObservability(owner, repo, ref?)` composing Part A (the snapshot's traces +
per-call eval pass-rates + cost/latency aggregates) and Part B (the repo
observability story from task 3 + teaching from task 5). Reads only the local DB
+ snapshot — offline, no network.

## Acceptance Criteria
- [ ] `getObservability(owner, repo, ref?)` returns a typed result with: the
      Part-A traces for that snapshot (with their evals), per-`traceName` aggregates
      (call count, eval pass-rate, total/avg cost + latency), and the Part-B story
      + teaching (or the `absent` state).
- [ ] Reads traces/evals from task-1 tables filtered by `snapshotId`, and the
      Part-B story by parsing `repo_files` via task 3 → task 5.
- [ ] The read path performs ZERO network calls and needs no API key — asserted.
- [ ] Returns a clean result for a snapshot with no traces yet (empty Part-A) and
      for a non-LLM repo (`absent` Part-B) — never an error.
- [ ] Public exports added to `packages/db/src/index.ts` + a `./observability`
      subpath in `package.json`, following the M12 `./ccpm` precedent.
- [ ] Vitest covers: traces + evals aggregation, empty Part-A, and the absent Part-B.

## Technical Details
- New file: `observability/index.ts` (+ `index.test.ts`); export from the package
  root + add the subpath export. Re-export the module's public types
  (`export * from "./cost" / "./detect" / "./teaching"` as needed) — mind the M12
  lesson: keep type names distinct to avoid `export *` collisions.
- Compose existing modules; this layer adds no new analysis — it queries + shapes.
- Mirror the M12 `getDeliveryMap` ergonomics (injectable `db`, `ref?` → latest).

## Dependencies
- 1 (trace/eval tables), 3 (analyzer), 5 (teaching).
