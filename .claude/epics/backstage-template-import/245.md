# Task: Enrichment companion format + loader

## Description

Define the typed, reviewable "enrichment companion" that supplies the coaching
fields a Backstage `template.yaml` does not carry, and a loader that pairs each
fixture template with its companion. This is what keeps imported entries fully
populated and reviewed (no naked output).

## Acceptance Criteria
- [ ] A typed `TemplateEnrichment` record carries the coaching fields Backstage
      lacks: `whyUsed`, `fitCriteria`, `fitFactors`, `risks`, `alternatives`,
      `learningNotes`, plus optional `category` override and extra `sources`.
- [ ] Field types reuse the existing schema JSON types (`TemplateFitFactor`,
      `TemplateRisk`, `TemplateAlternative`, `TemplateSource`) so enrichment and
      registry rows stay consistent.
- [ ] A loader pairs a fixture `template.yaml` with its enrichment companion by
      a stable convention (e.g. matching base name) and returns the typed pair.
- [ ] The loader fails clearly when a fixture has no companion or a companion is
      missing a required coaching field.
- [ ] Unit tests cover a valid pair and a missing/incomplete-companion failure.

## Technical Details
- New module `packages/db/src/template-enrichment.ts` (+ test).
- The companion may be authored as a typed `.ts` record (preferred for type
  safety) or a parsed data file — choose one and document it; reuse schema JSON
  types either way.

## Dependencies
- None (independent of #243). Consumed by the mapper (#246) and fixtures (#247).
