# Task: Provenance schema + migration + ADR

## Description

Extend the `templates` table with source provenance so imported Backstage
templates can coexist with the 15 curated entries and be told apart. This is the
foundation task: it lands the schema columns, the migration that backfills
existing rows, and the ADR recording the provenance + import-contract decision.

## Acceptance Criteria
- [ ] `templates` table (`packages/db/src/schema.ts`) gains: `source`
      (`'curated' | 'backstage'`, NOT NULL, default `'curated'`), `source_url`
      (text, nullable), `source_format` (text, nullable).
- [ ] A new Drizzle migration `0012_*.sql` is generated and the NOT-NULL default
      backfills all 15 existing rows to `source = 'curated'`.
- [ ] `templateSeed` entries in `template-seed-data.ts` explicitly set
      `source: 'curated'` (even though the default covers it).
- [ ] `Template` / `NewTemplate` types reflect the new columns (via inference).
- [ ] An ADR under `docs/decisions/` records AD-1 (same table + provenance),
      AD-2 (mapper + enrichment contract), AD-3 (fail-closed validation), and
      the `yaml` dependency choice.
- [ ] A test asserts the migration applies cleanly and curated rows carry
      `source = 'curated'` with null `source_url`/`source_format`.

## Technical Details
- Add columns in `schema.ts`; regenerate migration with the existing drizzle-kit
  flow (next number is `0012`). Do not hand-edit prior migrations.
- Default `'curated'` on a NOT-NULL column backfills existing rows on migrate.
- Data-access (`templates.ts`) needs no change — `select()` returns new columns.

## Dependencies
- None (foundation). Builds on the existing M3 `templates` schema + seed.
