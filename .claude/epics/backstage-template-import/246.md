# Task: Deterministic Backstage-to-registry mapper

## Description

The core of the importer: a pure function turning a parsed Backstage template +
its enrichment companion into a complete, valid `NewTemplate` registry row.
Deterministic, no IO, no network, no LLM — fully unit-testable.

## Acceptance Criteria
- [ ] `mapBackstageTemplate(parsed: BackstageTemplate, enrichment:
      TemplateEnrichment): NewTemplate` derives:
  - [ ] `slug` from `metadata.name`, namespaced to avoid collisions with curated
        slugs (e.g. `backstage-<name>`), kebab-case.
  - [ ] `name` from `metadata.title` ?? `metadata.name`.
  - [ ] `summary` from `metadata.description`.
  - [ ] `category` mapped from `spec.type`/`metadata.tags` into the registry
        vocabulary, overridable by the enrichment.
  - [ ] `whatItGenerates` derived deterministically from `spec.steps`/`spec.type`.
  - [ ] `sources` including the `template.yaml` origin URL plus enrichment
        sources.
  - [ ] coaching fields (`whyUsed`, `fitCriteria`, `fitFactors`, `risks`,
        `alternatives`, `learningNotes`) merged from the enrichment.
  - [ ] provenance: `source: 'backstage'`, `source_url`, `source_format`
        (`'backstage/scaffolder.v1beta3'`).
- [ ] Fail-closed: throws a clear error if any NOT-NULL registry field would be
      empty (AD-3).
- [ ] The function is pure — same inputs always produce the same row.
- [ ] Tests: a round-trip (fixture-shaped input → expected `NewTemplate`) and a
      missing-required-field failure.

## Technical Details
- New module `packages/db/src/backstage-import.ts` (+ test).
- Category mapping is a small deterministic lookup table from Backstage
  `spec.type` / tags to the existing registry categories.
