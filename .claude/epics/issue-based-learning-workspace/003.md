# Task: Generation call via Anthropic SDK + tool use + integrity check + mocked tests

## Description

Build the bounded Anthropic SDK call (per ADR 0005) that, given a normalized
`LearningUnitInput` from task 002, produces the typed seven-part learning
unit: restated goal, related files (with M6 role annotations where
available), concepts, AI-agent execution notes, review checklist,
understanding questions, and the minimal challenge stub
(`challenge_concept` / `challenge_type`). Implements FR-2, FR-3, FR-4, FR-7.

The call uses **tool use** to read specific snapshot files via the M11
snapshot data-access layer and to read M6 `project_maps` entries where they
exist — bounded reads, not whole-snapshot stuffing (NFR Bounded token use).
Per ADR 0005 this is a **bounded prompt → structured-output call** on the
shared `llm-foundation` Anthropic SDK client, **not** an autonomous agent
and **not** LangChain (LangChain stays confined to M6).

This task also lands the **file-reference integrity check at the generator
boundary** (FR-4): every related-file path must resolve to a real path in
the snapshot, every concept must tie to a related file or an M6 project-map
node, and every checklist item must be concrete to this issue. Unresolved
references **fail the unit** rather than silently rendering broken links.

## Acceptance Criteria
- [ ] A bounded Anthropic SDK call lives in `packages/ai/` (or the existing
      `llm-foundation` package path), exposed as e.g.
      `generateLearningUnit(input: LearningUnitInput): Promise<LearningUnit>`,
      and reuses the shipped `llm-foundation` client (ADR 0005).
- [ ] Structured output covers all **seven** parts (FR-2): `restatedGoal`,
      `relatedFiles[]`, `concepts[]`, `agentExecutionNotes`,
      `reviewChecklist[]`, `questions[]`, and the
      `challengeConcept` + `challengeType` stub (R3, FR-7) — typed and
      matching the `learning_units` schema columns from task 001.
- [ ] **Tool use** is wired so the SDK call can read specific snapshot files
      via the M11 snapshot data-access layer and read M6 `project_maps`
      rows via the project-maps data-access layer — bounded per call (NFR
      Bounded token use), not whole-snapshot stuffing.
- [ ] Graceful degradation (NFR Resilient): issues with no body produce a
      unit with an explicit "issue body empty" restated goal note; missing
      M6 map yields a unit with an explicit "project map unavailable"
      section; missing referenced snapshot files emit "file not in snapshot"
      annotations on the related-files entry rather than failing the whole
      call.
- [ ] **File-reference integrity check** at the generator boundary (FR-4):
      every `relatedFiles[].path` resolves against the M11 snapshot, every
      concept ties to a related file or M6 project-map node, every
      `reviewChecklist[]` item is concrete to this issue (references a
      file/concept). Unresolved references throw an `IntegrityError` and
      the unit is rejected — not silently rendered.
- [ ] Tested with **mocked / recorded** Anthropic SDK responses per the
      `llm-foundation` test strategy — including a fixture issue with valid
      refs, one with an unresolved file (integrity-check rejection), one
      with no body, and one with no M6 map. **No live API calls in CI**;
      tests run with no `ANTHROPIC_API_KEY` set (NFR Reproducible).
- [ ] The `questions[]` typed shape is **stable** and forms the input
      contract for task 004's grading call.
- [ ] `pnpm typecheck` and `pnpm test` pass.

## Technical Details

Per ADR 0005, the only SDK path is the `llm-foundation` Anthropic client;
LangChain remains confined to M6. Use the SDK's tool-use API to expose two
bounded tools to the model:

- `read_snapshot_file(path: string)` — proxies to the M11 snapshot
  data-access layer for a single bounded read.
- `read_project_map_node(nodeRef: string)` — proxies to the M6
  `project_maps` data-access layer; returns "not found" rather than
  throwing when no M6 map exists for the snapshot.

The prompt restates the goal, lists candidate related files (seeded from the
issue body's file mentions plus M6's key-file map where present), and
asks for the seven-part structured output. Use the SDK's structured-output
mechanism (JSON schema / tool-use response shape) — the response type must
match the `learning_units` columns from task 001 directly so persistence in
task 008 is mechanical.

The integrity check runs **inside** `generateLearningUnit` after the SDK
returns structured output and before the function resolves — this is the
mirror of M6's project-maps integrity check and M8's diff-reviews integrity
check (FR-4). On failure, throw a typed `IntegrityError` listing the
unresolved references.

`conflicts_with: ["004", "005"]` — this task introduces the typed
`LearningUnit` and `Question` shapes that tasks 004 and 005 also touch
(grading consumes the question shape; data-access stores the unit). Run
sequentially.

Test posture per ADR 0005 and `llm-foundation`: use the shared
mocked / recorded SDK response harness; no `ANTHROPIC_API_KEY` in CI; no
live network.
