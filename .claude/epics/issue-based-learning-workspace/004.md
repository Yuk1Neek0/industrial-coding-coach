# Task: Understanding-check grading call + mocked tests

## Description

Build the second bounded Anthropic SDK call: given a unit's typed
understanding questions (from task 003) and the user's answers, produce a
typed numeric **score** and a **weak-area breakdown** (FR-5). This is a
separate call from generation so the question set is fixed before any
answer is graded — the same separation pattern M8 ships for its diff-review
grading. Implements FR-5 and NFR "Fair grading".

The prompt and structured-output schema **match the M8 understanding-check
pattern** so M7 and M8 feel like one product, not two (per the epic's
Architecture Decisions and PRD NFR Fair grading). Per ADR 0005 this is a
bounded SDK call on the shipped `llm-foundation` client; no LangChain. Per
R6 scoring is strictly per-unit; no aggregate rollup is computed here (M10
owns that).

## Acceptance Criteria
- [ ] A bounded Anthropic SDK call lives in `packages/ai/` (or the
      `llm-foundation` path), exposed as e.g.
      `gradeLearningUnit(questions: Question[], answers: UserAnswer[]):
      Promise<{ score: Score, weakAreas: WeakArea[] }>`, reusing the shipped

- [ ] Structured output shape matches the M8 grading shape — typed `Score`

- [ ] **Per-unit scoring only** (R6) — no aggregate rollup, no cross-unit

- [ ] Tested with **mocked / recorded** Anthropic SDK responses per the
      `llm-foundation` test strategy: a fixture with all-correct answers, a

      with no `ANTHROPIC_API_KEY` set (NFR Reproducible).
- [ ] `pnpm typecheck` and `pnpm test` pass.

## Technical Details

Consumes the `Question[]` typed shape exported by task 003. The grading
call is **separate from generation** — the same separation M8 uses for its
review call vs. its grading call — so the question set is locked before any
answer is graded and the grading prompt does not have to re-infer the
questions.

Shape (illustrative):

```ts
type Score = { value: number; max: number; rubric?: string };
type WeakArea = { questionId: string; concept?: string; explanation: string };

export async function gradeLearningUnit(
  questions: Question[],
  answers: UserAnswer[],
): Promise<{ score: Score; weakAreas: WeakArea[] }>;
```

Match M8's grading prompt template / schema so the M8 and M7 UIs can share
the Score / Weak Area presentation (the M7 Understanding Questions UI in
task 006 explicitly mirrors M8's Score / Weak Area UI per the epic's
Technical Approach).

`conflicts_with: ["003", "005"]` — this task touches the same SDK-call
module surface as task 003 and the same persisted JSON columns as task 005;
run sequentially.

Per ADR 0005 only the `llm-foundation` client may be used; no LangChain.
Per `llm-foundation` test strategy: mocked / recorded SDK responses; CI runs
with no `ANTHROPIC_API_KEY` and no live network access.
