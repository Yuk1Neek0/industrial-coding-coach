# Task: Integrate M7 UI into apps/web

## Description

Integrate the **five** M7 UI pieces into `apps/web` and wire them to the
generation call (task 003), the grading call (task 004), the
`learning_units` data-access layer + integrity check (task 005), and the
extended M11 GitHub client (task 002). Mirrors the structure of the
shipped M6 integration task (task 108) and M8 integration task (task 116).
This is the final M7 task; on merge the milestone is feature-complete
modulo the Claude Design round-trip's draft + integration notes per ADR
0007.

Builds from the Page Specs and Claude Design prompts shipped by tasks 006
and 007. Routes are additive under `apps/web/app/repos/[owner]/[repo]/`;
no conflict expected with the shipped M6 / M8 integrations.

## Acceptance Criteria
- [ ] Per-repo Issues list page at
      `apps/web/app/repos/[owner]/[repo]/issues/page.tsx` lists issues for
      the imported repo via the task-002 issue-fetch surface; each row
      shows the learning-unit status badge (`not started | in progress |
      scored`) read from the task-005 data-access layer (R5, FR-11).
- [ ] Issue Learning Workspace page at
      `apps/web/app/repos/[owner]/[repo]/issues/[issueRef]/page.tsx`
      composes the Review Checklist UI, the Understanding Questions UI,
      and the Challenge Panel — built from the Claude Design drafts
      generated off task 006's Page Specs.
- [ ] On first visit to a unit's page, the route either reads an existing
      `learning_units` row or invokes the **generation call (task 003)**
      and persists the result via the task-005 data-access layer.
- [ ] Review Checklist UI persists per-item state to
      `learning_units.checklist_state` (FR-6) and shows it as a progress
      indicator only — **does not gate the score** (R4).
- [ ] Understanding Questions UI posts answers, invokes the **grading call
      (task 004)**, persists the typed `Score` + `WeakArea[]` to
      `learning_units.score` / `learning_units.weak_areas`, and renders
      the Score / Weak Area block matching M8's shape.
- [ ] Challenge Panel renders only the `challenge_concept` /
      `challenge_type` stub and an explicit "**deferred to M9**" message
      (FR-7, R3) — does not run, grade, or claim to resolve a challenge.
- [ ] File references shown on every M7 page pass
      `verifyLearningUnitIntegrity` from task 005 (FR-4); unresolved refs
      surface an explicit failure state, not a silent broken link.
- [ ] Claude Design **integration notes** are written under
      `docs/design/ui-integration-notes/` for each of the five UIs
      (ADR 0007 round-trip: Page Spec → prompt → draft → integration notes).
- [ ] The five pages are reachable from the imported-repo page off the
      "Issues" tab per R5; no global cross-repo issues route is added.
- [ ] End-to-end happy-path test (mocked SDK + mocked GitHub) covers:
      open a unit, see related files / concepts / agent notes, mark one
      checklist item, answer the questions, receive a score and weak-area
      breakdown, and re-load the page to see persisted state.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm build`, `pnpm test` pass with
      **no `ANTHROPIC_API_KEY` set and no live GitHub calls in CI**.

## Technical Details

Build the five pages from the Page Specs + Claude Design drafts shipped by
tasks 006 and 007. Per ADR 0007, the round-trip is Page Spec → prompt →
Claude Design draft → Claude Code integration with notes under
`docs/design/ui-integration-notes/`. This task closes the round-trip with
the integration step and the notes file per page.

Per-repo route shape (additive under existing `apps/web/app/repos/`):

```
apps/web/app/repos/[owner]/[repo]/issues/page.tsx                 # task 007 spec
apps/web/app/repos/[owner]/[repo]/issues/[issueRef]/page.tsx      # task 006 spec
```

Server actions / route handlers under `apps/web/app/repos/[owner]/[repo]/issues/`
invoke `generateLearningUnit` (task 003), `gradeLearningUnit` (task 004),
and the task-005 data-access layer; the issue list fetches via the
task-002 client. Routes are additive — coordinate with the shipped M6 / M8
routes (no conflict expected; M6 and M8 are already merged).

**Integration-boundary integrity check**: before rendering, call
`verifyLearningUnitIntegrity(unit, snapshotFiles, projectMap?)` from
task 005 (FR-4). On unresolved refs, render an explicit error state —
mirrors how M6 and M8 handle their integrity rejections.

**Test posture**: end-to-end happy-path test uses the mocked SDK harness
from `llm-foundation` and mocked GitHub responses from task 002. CI runs
with no `ANTHROPIC_API_KEY` and no `GITHUB_TOKEN` (NFR Reproducible per
ADR 0005).

**ADR 0008** — this task is the Wave 4 sequential integration; it runs
on the `epic/issue-based-learning-workspace` branch and merges to `main`
via PR per the parallel-execution model.
