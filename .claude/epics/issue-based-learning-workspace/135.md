# Task: learning_units data-access layer + file-reference integrity check

## Description

Build the typed data-access layer for `learning_units`: create, read, and
update a unit and its JSON columns (`user_answers`, `score`, `weak_areas`,
`checklist_state`) — all on the single `learning_units` row (R2, FR-8,
FR-9). Mirrors the data-access patterns from M6 `project_maps` and M8
`diff_reviews`.

Also lands the **persistence-layer file-reference integrity check (FR-4)** —
a reusable validator that, given a `LearningUnit` and the imported
snapshot's file set, verifies every related-file path resolves, every
concept ties to a related file or M6 project-map node, and every checklist
item is concrete. The same check is invoked at the generator boundary in
task 003 and at the integration boundary in task 008; this task is its
durable home.

## Technical Details

Mirror the data-access pattern in `packages/db/src/mapper/` (M6
project-maps) and `packages/db/src/diff/` (M8 diff-reviews). The module is
**server-side only**; no UI imports here.

Shape (illustrative):

```ts
// packages/db/src/learning-units/index.ts
export async function createLearningUnit(unit: NewLearningUnit): Promise<LearningUnit>;
export async function getLearningUnit(repoId: number, issueRef: string): Promise<LearningUnit | null>;
export async function updateLearningUnit(id: number, patch: Partial<LearningUnit>): Promise<LearningUnit>;
export async function recordAnswers(id: number, answers: UserAnswer[]): Promise<void>;
export async function recordScore(id: number, score: Score, weakAreas: WeakArea[]): Promise<void>;
export async function updateChecklistState(id: number, state: ChecklistState): Promise<void>;

export function verifyLearningUnitIntegrity(
  unit: LearningUnit,
  snapshotFiles: Set<string>,
  projectMap?: ProjectMap,
): { ok: boolean; unresolved: UnresolvedRef[] };
```

The integrity check is the **reusable** validator: task 003 calls it at the
generator boundary (rejecting LLM output), task 008 calls it at the
integration boundary (guarding UI rendering). Keep it pure and
synchronous; do not bake snapshot-fetching into it (callers supply the
file set).

**Per R4 the data-access layer does not gate** — `checklist_state` is
persisted for display, never used to block scoring. Scoring is strictly
per-unit (R6); this module does not compute any cross-unit aggregate.

`conflicts_with: ["003", "004"]` — this task touches the same typed
`LearningUnit`, `UserAnswer`, `Score`, `WeakArea` shapes as the SDK-call
tasks; run sequentially.
