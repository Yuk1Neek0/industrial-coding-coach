# Task: Server-side LLM client wrapper + typed error module

## Description

Build the server-side LLM client wrapper in `packages/ai`: a typed API for a
bounded prompt → structured-output call on the Anthropic SDK, plus a typed error
module. This is the interface M4 and M5 will build their LLM calls on. It is a
thin, reviewable wrapper — not an abstraction layer, not an agent framework
(ADR 0005).

## Acceptance Criteria
- [ ] A typed call API is exported from `packages/ai` for a bounded
      prompt → structured-output invocation.
- [ ] The wrapper supports the three ADR 0005 capabilities: prompt caching, tool
      use, and structured outputs.
- [ ] SDK calls go through an injectable client interface so a mock can be
      substituted in tests.
- [ ] A typed error module maps missing key, rate limit, API failure, and
      timeout to typed errors, mirroring `packages/db/src/github` error handling.
- [ ] The default Claude model is configurable and documented.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm build` pass.

## Technical Details

The injectable-client seam is what makes task 3's CI-safe tests possible — keep
the live SDK behind that interface. Prompt caching is enabled by default.

## Dependencies

Task 1 (package scaffold + SDK + config accessor).
