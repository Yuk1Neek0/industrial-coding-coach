# Task: Deterministic composition module

## Description

Build the three pure-TS composers that produce M10's **structural**
artifacts (FR-2): architecture explanation, learning memory tree, debug
stories. No SDK call — these are deterministic renderers over the
shipped M5/M6/M7/M8/M9 rows so the structural artifacts can never
hallucinate against the data the user already understood.

## Acceptance Criteria

- [ ] `packages/db/src/learning-memories/compose.ts` exports:
      - `composeArchitectureExplanation(snapshotId): Promise<ArchitectureExplanation>`
        — reads `stack_explanations` + `project_maps`; emits ~1–2 pages
        of markdown (typed shape with `intro`, `stackSection`,
        `architectureSection`, `keyFlowsSection`) grounded in the named
        files; every section cites real file paths from the M6 map and
        real technology names from M5.
      - `composeLearningMemoryTree(snapshotId): Promise<LearningMemoryTree>`
        — reads `learning_units` (incl. `weak_areas`), `diff_reviews`
        (incl. `weak_areas`), and `challenge_attempts.grading.weakAreas`;
        emits a typed tree with leaves that cite the row that taught
        each concept and a separate `stillToRevisit` branch surfacing
        every weak-area entry (FR-4).
      - `composeDebugStories(snapshotId): Promise<DebugStory[]>` — reads
        `challenge_attempts` + their parent `challenges`; emits a typed
        per-attempt narrative (`challengeType`, `taskSummary`,
        `explanationExcerpt`, `gradingResult`).
- [ ] Pure functions: no SDK import, no random / time-dependent input
      apart from reading the database. Calling twice on identical seeded
      data must yield byte-identical results (NFR-2).
- [ ] Stable ordering: outputs sort by `repo_snapshots.id` chronology
      then by foreign-key id (no Map / Set iteration order leaks).
- [ ] Unit tests with seeded SQLite fixtures cover:
      - All three composers on a richly seeded snapshot.
      - Weak-area surface: a learning_unit + a diff_review +
        a challenge_attempt each contributing a `stillToRevisit` entry.
      - Empty-input degradation: missing M5 / M6 / M7 / M8 / M9 rows
        each emit explicit "none yet" sections rather than throwing.
      - Reproducibility: two calls on the same fixture produce
        identical JSON.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` pass.

## Technical Details

- Read via the existing M5 / M6 / M7 / M8 / M9 DALs; no direct Drizzle
  queries here.
- Composer outputs are TS objects, *not* strings. The markdown
  serialization happens later in task 7 (markdown bundle exporter).
  Keeping the composers structural lets the Portfolio Page bind to
  typed fields and lets the exporter render once.
- Reuse M8's `WeakArea` shape verbatim — same type imported from
  `@workspace/db`. Do not redefine.

## Dependencies

`DebugStory` types are declared there).
Out-of-epic: M5/M6/M7/M8/M9 DALs (shipped).
