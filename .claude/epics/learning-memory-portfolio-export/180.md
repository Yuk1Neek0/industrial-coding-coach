# Task: Interview Q&A bounded SDK call

## Description

The first of M10's two narrative-generation calls (FR-2): a bounded
Anthropic SDK call on the shipped `llm-foundation` client that produces
a typed `InterviewQA[]` covering the five ground areas named in the PRD
— stack (M5), architecture (M6), per-issue learning (M7), diff / risk
reading (M8), and debug / expansion reasoning (M9). Tool use reads
specific rows from each of those tables; a forced final
`submit_interview_qa` tool yields the structured output. The output
runs through the integrity check (task 002) before persistence; failing
outputs are rejected, not softened (NFR-5).

## Acceptance Criteria

- [ ] `packages/db/src/learning-memories/generate-qa.ts` exports
      `generateInterviewQA(snapshotId): Promise<InterviewQA[]>`.
- [ ] Bounded SDK call on `@workspace/ai`:
      - Fixed tool set: `read_stack_explanation`, `read_project_map_entry`,
        `read_learning_unit`, `read_diff_review`,
        `read_challenge_attempt`, `submit_interview_qa` (forced final).
      - Short turn cap (≤ 6) with `submit_interview_qa` forced on the
        last turn — same shape as M8's `reviewDiff`.
      - System prompt names the five ground areas and rejects
        generic-tutorial questions.
- [ ] Output passes the integrity check from task 002. If
      `checkArtifactIntegrity` returns `ok: false`, throw with the
      `missing` list — do not persist a partial / softened version.
- [ ] Tests run on the `@workspace/ai` mock transport:
      - A "happy path" fixture with seeded M5/M6/M7/M8/M9 rows produces
        ≥ one question per ground area.
      - A "hallucinated path" fixture (mocked response naming a file
        not in the M6 map) is rejected with the missing-references list.
      - Empty / partial source data (e.g. no `challenge_attempts` rows)
        skips that ground area rather than fabricating one.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` pass with **no**
      `ANTHROPIC_API_KEY` set.

## Technical Details

- Use the M7 / M8 / M9 `generate.ts` files as the template — same
  `@workspace/ai` import surface, same forced-tool shape, same mock
  test pattern.
- The `InterviewQA` TS type is declared in task 001's
  `schema.ts` exports.
- Output is intended to be cached on the `learning_memories.interview_qa`
  column by the caller (task 009). This task only generates +
  integrity-checks; persistence is the caller's job.
- Listed as `conflicts_with: [6]` because task 006 (résumé bullets)
  shares the `packages/db/src/learning-memories/index.ts` barrel and
  may touch shared scaffolding (tool definitions, prompt helpers).
  Sequencing 5 → 6 (per `depends_on` on task 006) avoids the merge
  conflict.
