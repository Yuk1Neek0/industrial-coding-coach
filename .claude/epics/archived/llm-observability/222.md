# Task: Recording LlmClient decorator + recordEval

## Description

Create `packages/db/src/observability/record.ts` — the instrumentation seam:
`createObservedLlmClient({ traceName, snapshotId, db, model? })` wraps a
`@workspace/ai` `LlmClient` so each `complete()` turn records an observation and
the turns aggregate into one `llm_traces` row; plus `recordEval(traceRef, {
check, passed, reason })` writing an `llm_evals` row. All writes are best-effort
and non-blocking (AD-2).

## Acceptance Criteria
- [ ] `createObservedLlmClient(opts)` returns an `LlmClient` whose `complete()`
      calls the inner client, captures model + `usage` + latency + outcome per
      turn, and persists a trace (aggregating tokens, estimated cost via task 2,
      latency, and a typed outcome) keyed by `traceName`/`snapshotId`.
- [ ] Multi-turn tool-use loops aggregate into ONE trace with per-turn entries in
      the JSON `observations` column.
- [ ] A failed `complete()` records a trace with the failure kind; the inner
      `LlmResult` is returned **unchanged** to the caller.
- [ ] **Non-blocking:** every observability write is wrapped so a thrown write
      error is swallowed + logged and never changes the call's result or latency —
      asserted by a test that forces the recorder DB to throw.
- [ ] `recordEval(...)` writes an `llm_evals` row tied to the trace; also best-effort.
- [ ] Injectable `db` (tests) + a way to associate the eval with the just-made
      trace (e.g. the observed client exposes the trace id / a handle).
- [ ] Vitest with a mocked transport + in-memory DB covers: success trace, failure
      trace, multi-turn aggregation, recordEval, and the forced-write-failure
      non-blocking guarantee.

## Technical Details
- New file: `observability/record.ts` (+ `record.test.ts`). Wraps the
  `@workspace/ai` `LlmClient` interface (it already returns `usage`); reuses the
  task-2 cost estimator; writes via the task-1 schema.
- Best-effort pattern: a private `safeWrite(fn)` that try/catches and logs.
- Do NOT edit the bounded calls here (that is task 6) — this task only provides
  the seam + its tests.
