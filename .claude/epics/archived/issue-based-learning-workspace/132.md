# Task: Issue fetching in M11 GitHub client + CCPM-task adapter + normalized input + tests

## Description

Extend the shipped M11 GitHub client at `packages/db/src/github` with
read-only **issue** endpoints — number, title, body, labels, state, linked
PRs — reusing its existing authentication, `GITHUB_TOKEN` mechanism, and
rate-limit handling per ADR 0009. Mirrors how M8 extended the same client
with PR fetching; M7 must not introduce a second GitHub access path.

Also build a **CCPM-task local adapter** that reads
`.claude/epics/<epic>/<task>.md` files from the imported snapshot where they
exist, and a **normalized learning-unit input shape** (R1, FR-1) that both
GitHub Issues and CCPM tasks fold into. Downstream (the generation call in
task 003) consumes only the normalized shape; the `source` field is metadata.

## Acceptance Criteria
- [ ] Issue endpoints added to the existing client module
      `packages/db/src/github/` — **not** a new module — exposing a typed
      `fetchIssue(repoIdentity, issueNumber)` and `listIssues(repoIdentity)`
      that return number, title, body, labels, state, and linked PR refs
      (FR-1).
- [ ] Reuses the existing client's authentication, `GITHUB_TOKEN`
      mechanism, and rate-limit handling per ADR 0009 — no second access
      path, no new auth code.
- [ ] PR-fetching shipped in M8 is left intact and untouched.
- [ ] CCPM-task local adapter at `packages/db/src/github/ccpm-task-adapter.ts`
      (or sibling) reads `.claude/epics/<epic>/<task>.md` files from the
      imported snapshot via the M11 snapshot data-access layer, parses their

- [ ] A typed normalized input shape (R1) — e.g. `LearningUnitInput` exported

      'ccpm-task'`, a stable `issueRef` string, `title`, `body`, `labels`,
      `state`, and `linkedPrs` (empty for CCPM tasks). The unit and the

- [ ] Tests under `packages/db/src/github/*.test.ts` cover: issue fetch with
      mocked GitHub responses, the CCPM-task adapter against fixture task

      linked PR, and a repo with no CCPM tasks. **No live GitHub calls in
      CI**; tests run with no `GITHUB_TOKEN` set (NFR Reproducible).
- [ ] `pnpm typecheck` and `pnpm test` pass.

## Technical Details

Mirror the M8 PR-fetch extension to the M11 client (see how the existing
`packages/db/src/github` module surfaces PR endpoints) — add issue endpoints
side-by-side rather than creating a new file. The typed
`LearningUnitInput` is the **input contract** for task 003's generation call,
so its shape must be stable and exported before task 003 starts.

CCPM task files live under `.claude/epics/<epic>/<task>.md` inside the
imported snapshot (some repos use CCPM); the adapter reads them via the M11
snapshot data-access layer (NOT live filesystem) so behavior is
snapshot-deterministic. Parse the standard CCPM frontmatter (`name`,
`status`, `github`, `depends_on`) per
`.claude/skills/ccpm/references/conventions.md` and treat the markdown body
as the `body` field.

GitHub access is **read-only** per ADR 0009 — fetch only. No issue creation,
no comment writes, no closes. Test posture per ADR 0005 and `llm-foundation`:
mocked / recorded responses only; CI runs with no `GITHUB_TOKEN` and no live
network access.
