# Task: learning_units schema + Drizzle migration

## Description

Add a single `learning_units` table to the existing SQLite database (ADR 0006)
to persist M7 learning units, the user's answers, the per-attempt score, the
weak-area breakdown, and the review-checklist state — all on one row, with
JSON columns (R2). Generate the Drizzle migration. No companion tables, no new
database; mirrors how M6 `project_maps` and M8 `diff_reviews` ship a single
table with JSON columns.

This task delivers the persistence foundation FR-8 / R2 require and unblocks
the data-access layer (task 005). Per R3 the migration adds only the **minimal
`challenge_concept` / `challenge_type` stub columns** — M9 will land its full
challenge schema in its own migration when M9 ships; M7 pre-allocates nothing
for M9.

## Technical Details

Follow the existing conventions in `packages/db/src/schema.ts` for
`project_maps` and `diff_reviews`. Use Drizzle's `sqliteTable` with a
composite-friendly primary key (repo + issue/task ref + source) or a
synthetic `id` plus a unique index over `(repo, issue_ref, source)`. Store
all list / structured fields as JSON columns (`text({ mode: 'json' })`) per
ADR 0006 and R2.

Schema shape (illustrative):

```ts
learning_units = sqliteTable('learning_units', {
  id: integer().primaryKey({ autoIncrement: true }),
  snapshotId: integer().notNull(),         // FK shape per existing tables
  source: text({ enum: ['github-issue', 'ccpm-task'] }).notNull(),
  issueRef: text().notNull(),              // e.g. "#42" or "epic/foo/003"
  restatedGoal: text().notNull(),
  relatedFiles: text({ mode: 'json' }).notNull(),
  concepts: text({ mode: 'json' }).notNull(),
  agentExecutionNotes: text().notNull(),
  reviewChecklist: text({ mode: 'json' }).notNull(),
  questions: text({ mode: 'json' }).notNull(),
  challengeConcept: text(),                // R3 stub
  challengeType: text(),                   // R3 stub
  userAnswers: text({ mode: 'json' }),     // R2
  score: text({ mode: 'json' }),           // R2
  weakAreas: text({ mode: 'json' }),       // R2
  checklistState: text({ mode: 'json' }),  // R2, R4
  createdAt: integer({ mode: 'timestamp' }).notNull(),
  updatedAt: integer({ mode: 'timestamp' }).notNull(),
})
```

Migration numbering is resolved at epic merge time (M7 lands after M6 and M8
have shipped, so it follows their numbering). Cite ADR 0006 (storage) and R2
in the migration's commit-time review. Do **not** add M9 challenge columns
(R3) — `challenge_concept` and `challenge_type` are the entire stub surface.
