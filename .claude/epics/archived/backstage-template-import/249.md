# Task: Registry UI provenance affordance

## Description

Surface template provenance in the Template Registry UI so a user can see that a
template came from Backstage and follow it to its source, while curated entries
read as internally curated.

## Acceptance Criteria
- [ ] Imported templates show a "Source: Backstage" badge in the registry list
      (`template-card.tsx`) and on the detail view (`detail-view.tsx`).
- [ ] The badge/detail links to the template's `source_url` (opens the upstream
      `template.yaml` origin).
- [ ] Curated templates show no Backstage badge (rendered as internally curated).
- [ ] The list and detail pages render correctly for both sources after seeding;
      `pnpm build` for the web app passes.
- [ ] If new page structure is required, a Page Spec delta under `docs/design/`
      and a v0 draft precede integration (v0 rule); a badge/link on existing
      pages is a direct bounded integration and does not require v0.

## Technical Details
- Edit `apps/web/app/templates/_components/template-card.tsx` and
  `detail-view.tsx`; minor styles in `templates.css` if needed.
- Read provenance from the `Template` row (already returned by data-access).
