# Task: Backstage template model + YAML parser

## Description

Add a typed representation of the subset of a Backstage software template
(`kind: Template`, `scaffolder.backstage.io/v1beta3`) the importer consumes, and
a parser that turns raw `template.yaml` text into that typed model with
validation of required fields.

## Acceptance Criteria
- [ ] The `yaml` package is added as a dependency to `packages/db` (installed per
      its official docs/README; recorded in the task #243 ADR/setup note).
- [ ] A typed `BackstageTemplate` covers: `apiVersion`, `kind`, `metadata`
      (`name`, `title`, `description`, `tags`, `annotations`), `spec` (`type`,
      `owner`, `parameters`, `steps`).
- [ ] `parseBackstageTemplate(yamlText: string): BackstageTemplate` parses YAML
      and validates required fields (e.g. `kind === 'Template'`, `metadata.name`,
      `spec.type`).
- [ ] Parsing malformed YAML or a non-Template / missing-required-field document
      throws a clear, typed error.
- [ ] Unit tests cover a valid parse, a malformed-YAML failure, and a
      missing-required-field failure.

## Technical Details
- New module `packages/db/src/backstage-template.ts` (+ test).
- Use the `yaml` library's parse; do not write a bespoke YAML parser (AD-5).
- Keep the model a *subset* — only fields the mapper needs.

## Dependencies
- None (independent of #243). Provides the input type the mapper (#246) uses.
