# Epic: github-integration

## Overview

Build the GitHub Integration MVP (Milestone 11, pulled forward): the ability to
import a GitHub repository by URL — its file tree, key files, and metadata —
into a local snapshot, plus an import UI. This is the repo-ingestion foundation
that unblocks M5 (Stack Decision Explainer) and later analysis milestones. It
introduces the product's first network dependency.

## Architecture Decisions

- **New ADR required:** a GitHub-access ADR records authentication, rate-limit
  handling, and snapshot storage. It is the first deliverable of this epic
  (task 001) — the schema/storage choice depends on it.
- **Storage:** a local snapshot per imported repo, keyed by `owner/repo` + ref.
  Default leaning: a new table set in the existing catalog SQLite DB (ADR 0006);
  the ADR confirms SQLite vs. a file cache.
- **Access:** GitHub REST API (or `gh` CLI) with a token read from `.env`;
  read-only scope; selective file fetching to respect rate limits.
- **Local-first preserved:** GitHub is contacted only at import time; downstream
  analysis reads the local snapshot.
- **Import UI:** built via the **v0 round-trip** — page spec + v0 prompt
  authored here, generated by the user in v0, then integrated.
- **MVP boundary:** tree + key files + metadata only. Issues/PRs/diffs deferred.

## Technical Approach

### Frontend Components

- An **Import page** in `apps/web` — enter a repo URL (+ optional ref), trigger
  import, show status and result (or a clear error). Built from a page spec via
  v0, using `packages/ui` (shadcn/ui).

### Backend Services

- A GitHub API client (auth, fetch tree, fetch file contents, fetch metadata,
  rate-limit + error handling) in `packages/db` or a new package.
- A repo-import module that, given `owner/repo`, selects key files
  (`package.json`, lockfiles, framework/build config, README, CI workflows) and
  writes a local snapshot.
- A typed data-access layer: import a repo, list imported repos, get a repo's
  tree, get a file's content.

### Infrastructure

- Drizzle schema + migration for the snapshot store (pending the ADR).
- `.env.example` documents the GitHub token variable; no token committed.

## Implementation Strategy

001 settles the GitHub-access ADR and the snapshot schema/migration
(foundational — everything depends on it). 002 builds the GitHub API client +
auth. 003 builds the import module + key-file selection on top of the client.
004 adds the typed data-access layer + tests. 002→003→004 is largely a chain
(typical within an epic). 005 (the Import page spec + v0 prompt) can be written
from the PRD at any time and ends in a **hand-off to the user**. 006 integrates
the v0 output last.

## Success Criteria (Technical)

- A public repo imports by URL: tree + key files + metadata land in local
  storage; created reproducibly via migration.
- A private repo imports successfully with a valid token configured.
- Invalid URL, repo-not-found, rate-limit, and auth-failure errors are surfaced
  clearly.
- Data-access layer typed and tested (import, list, get tree, get file).
- The Import page can import a repo and show its result.
- `pnpm lint`, `pnpm typecheck`, `pnpm build` pass; CI green; no token committed.
