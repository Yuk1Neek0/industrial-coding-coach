# Task: ADR 0011 — schema-collision discipline + epic-merge checklist

## Description

The M9 retrospective flags (overdue from M8) that parallel epics colliding on
`packages/db/src/schema.ts` + Drizzle migrations need an agreed rule before
the next parallel-schema epic. Write it down: an ADR recording the
discipline, plus a merge-time checklist where future epic merges will find
it.

## Acceptance Criteria

- [ ] `docs/decisions/0011-schema-collision-discipline.md` exists, follows
      the existing ADR format (see `0010-backstage-import-contract.md` for
      shape), and records:
      - Default rule: only one epic touches `packages/db/src/schema.ts` +
        `drizzle/` migrations at a time; other epics rebase after that schema
        lands on `main`.
      - Escape hatch: if parallel schema work is unavoidable, the merging
        epic regenerates its migration as `N+1` via `drizzle-kit generate`
        against main's latest snapshot before merge (the M9 collision
        playbook), with the concrete steps listed.
- [ ] The epic-merge checklist (the regenerate-as-N+1 steps) is recorded
      where epic merges are documented (e.g. a short section in the ADR
      referenced from `docs/decisions/README.md` or the docs index — follow
      where ADR 0008's worktree workflow is referenced).
- [ ] ADR status/date/context/decision/consequences sections complete; links
      to the M8/M9 retrospectives that motivated it.
- [ ] `pnpm lint` unaffected (docs-only change).
