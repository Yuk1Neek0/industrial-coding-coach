# Task: Reusable file + stack-reference integrity check

## Description

Build the shared integrity-check module that the two bounded SDK calls
(tasks 5 + 6) consume to verify every file / stack reference in a
generated artifact resolves to a real row (FR-3, NFR-5). Adapt M9's
`packages/db/src/challenges/integrity-check.ts` — same shape, broader
inputs: M9 checks against `project_maps` only; M10 checks against
`project_maps` *and* `stack_explanations`.

## Acceptance Criteria

- [ ] `packages/db/src/learning-memories/integrity.ts` exports:
      `checkFileReferences(snapshotId, paths: string[]): IntegrityResult`
      (every path must be in the M6 project-map file set),
      `checkStackReferences(snapshotId, technologies: string[]): IntegrityResult`
      (every named technology must resolve to a real M5
      `stack_explanations` row), and a combined
      `checkArtifactIntegrity` helper for the typed `InterviewQA[]` and
      `ResumeBullet[]` shapes that pulls out the references and runs
      both checks.
- [ ] `IntegrityResult` shape: `{ ok: true } | { ok: false, missing:
      string[] }` — same shape M9 used so consumers feel identical.
- [ ] Pure function: takes the snapshot id and the to-check arrays; the
      M5/M6 DAL fetches happen inside the module. No SDK imports.
- [ ] Unit tests on seeded fixtures: all-resolved → `ok`,
      partially-missing → `ok: false` with the right `missing` list,
      empty inputs → `ok`, case-sensitivity matches M9's behaviour.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` pass.

## Technical Details

- Read the existing M9 module (`packages/db/src/challenges/integrity-check.ts`)
  and follow its public shape so consumers learn one API.
- Use the M6 project-map DAL (`packages/db/src/mapper/`) for file
  paths and the M5 stack-explanations DAL for technology names. Do not
  re-query Drizzle directly.
- The module is *consumed* by tasks 5 and 6; it does **not** reject
  outputs itself — it returns the result and lets the caller persist or
  throw. Keeps it composable.

## Dependencies

None in-epic. Reads M5 `stack_explanations` (shipped) and M6
`project_maps` (shipped) via their DALs.
