# Task: Markdown bundle exporter

## Description

Render a `learning_memories` row as the per-type markdown files plus a
combined `portfolio.md`, packaged as a downloadable ZIP. Filenames
include `owner-repo-snapshot.id` (US-6) so multiple imported repos do
not collide on the user's disk.

## Acceptance Criteria

- [ ] `packages/db/src/learning-memories/export-markdown.ts` exports
      `renderPortfolioMarkdownBundle(memory: LearningMemory):
      Promise<{ files: Record<string, string>; zip: Buffer }>` —
      returns both the in-memory file map (for tests / page-side
      rendering) and the zipped buffer (for Server Action download).
- [ ] Bundle contents (filenames literal):
      - `architecture.md` — `architecture_explanation` rendered.
      - `learning-memory-tree.md` — `learning_memory_tree` rendered;
        weak-area "still to revisit" branch surfaced (FR-4).
      - `interview-qa.md` — `interview_qa` rendered with each Q + A
        block.
      - `resume-bullets.md` — `resume_bullets` rendered as a markdown
        list.
      - `debug-stories.md` — `debug_stories` rendered, one section per
        attempt.
      - `portfolio.md` — combined bundle in the same fixed order as
        the Portfolio Page (architecture → memory tree → Q&A → bullets
        → debug stories).
- [ ] ZIP filename: `portfolio-<owner>-<repo>-<snapshot.id>.zip` —
      slug-safe `owner` / `repo` (lowercase, `/` → `-`).
- [ ] Bundle is fully reproducible — running the renderer twice on the
      same memory row + the same snapshot produces byte-identical files
      (matches NFR-2).
- [ ] Tests on seeded fixtures: golden-file comparison for each
      rendered file; ZIP unpacks to the same six files.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` pass.

## Technical Details

- Use a lightweight zip library already on the trial-track or vetted
  for size (e.g. `jszip` or `fflate`). Choice locked in this task's
  setup note; reuse the M0.10 tool-radar / install-rule conventions.
- The composers in task 004 produce typed objects; this task is the
  *only* place that serializes those objects to markdown. Keeps the
  composers reusable for the Portfolio Page render too.
- Slug helper: `owner`/`repo` come from `repo_snapshots`; sanitize for
  filesystems (lowercase, replace `/`, spaces, and any
  filesystem-unsafe chars with `-`).

## Dependencies

In-epic: tasks 004 (composer outputs), 005 + 006 (SDK-generated
payloads).
Out-of-epic: small zip dependency (selected and recorded in this task).
