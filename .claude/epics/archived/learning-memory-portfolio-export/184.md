# Task: Integrate Portfolio Page + actions into `apps/web`

## Description

Wave 4. Wire the M10 backend to the user: build the Portfolio Page route
at `/portfolio/[owner]/[repo]` per the Page Spec (task 003), implement
the three Server Actions (regenerate / export-markdown / export-PDF),
show the stale-data banner (FR-11), and complete the Claude Design
round-trip by filling in
`docs/design/ui-integration-notes/portfolio-page.md`. End-to-end loop
verified on a seeded sample repo.

## Acceptance Criteria

- [ ] Route `apps/web/app/portfolio/[owner]/[repo]/page.tsx` renders the
      page per task 003's Page Spec (sections in fixed order, anchor
      nav, the three actions, stale-data banner).
- [ ] Server Actions in `apps/web/app/portfolio/[owner]/[repo]/actions.ts`:
      - `regenerateMemory(snapshotId)` — runs `generateInterviewQA` +
        `generateResumeBullets` + the three composers, integrity-checks,
        upserts `learning_memories`, revalidates the route.
      - `exportPortfolioBundle(snapshotId)` — returns the markdown ZIP
        as a streamed response.
      - `exportPortfolioPdf(snapshotId)` — returns the PDF as a streamed
        response.
- [ ] Loading / error / not-found UI for the route follows the M7 / M9
      pattern (separate `loading.tsx` / `error.tsx` / `not-found.tsx`).
- [ ] Nav entry — a `chrome.tsx` link to `/portfolio/[owner]/[repo]` on
      the imported-repo page. (Same per-feature nav pattern called out
      as a recurring follow-up across M7 / M8 / M9 — flag in the PR
      that the unifying nav pass is still unscoped.)
- [ ] `docs/design/ui-integration-notes/portfolio-page.md` filled in:
      shipped types vs. Page-Spec types, any deviations + reason, route
      decisions, drift watch (guard against the M8 retro lesson).
- [ ] End-to-end manual verification on a seeded sample repo: open the
      page → see deterministic sections render with no API key → click
      "Regenerate" with `ANTHROPIC_API_KEY` set → see all five sections
      populated → click "Export bundle" → ZIP downloads → click "Export
      PDF" → PDF downloads. Recorded in the integration notes.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm build`, `pnpm test` pass
      *with no API key set* (the regenerate Server Action requires one
      at runtime but the build / tests do not).

## Technical Details

- LLM and DAL calls run **server-side only** — Server Actions, not
  client components. Matches M7 / M8 / M9.
- The stale-data banner reads `isMemoryStale(snapshotId)` from task
  001's DAL.
- ZIP / PDF responses: use the Server Action's Response API; set
  `Content-Disposition: attachment; filename="..."` with the slug
  filenames from tasks 007 / 008.
- Cache strategy: revalidate on `regenerateMemory`. No on-snapshot-write
  auto-regeneration (FR-5).

## Dependencies
