# Task: `learning_memories` schema + Drizzle migration + DAL

## Description

Add the single `learning_memories` table that backs M10's per-repo cache
of generated artifacts (interview Q&A, résumé bullets, architecture
explanation, learning memory tree, debug stories) plus the typed
data-access layer for create / read / upsert / stale-check. Keyed by
`snapshot_id` (unique). Same one-table-per-milestone JSON-columns shape
as M6 / M7 / M8 / M9 (ADR 0006).

## Acceptance Criteria

- [ ] `packages/db/src/schema.ts` declares a `learningMemories` table:
      `id` (PK autoincrement), `snapshot_id` (FK → `repo_snapshots.id`,
      `ON DELETE CASCADE`, **unique**), JSON text columns `interview_qa`,
      `resume_bullets`, `architecture_explanation`,
      `learning_memory_tree`, `debug_stories`, plus `generated_at`,
      `created_at`, `updated_at` (epoch integers).
- [ ] Exported types: `LearningMemory`, `NewLearningMemory`, plus
      structural TS interfaces for each JSON column's payload
      (`InterviewQA`, `ResumeBullet`, `ArchitectureExplanation`,
      `LearningMemoryTree`, `DebugStory[]`).
- [ ] Drizzle migration generated as `0009_*.sql` via
      `pnpm --filter @workspace/db db:generate` (clean run on top of
      M9's `0008_wealthy_starbolt.sql`).
- [ ] DAL module at `packages/db/src/learning-memories/memories.ts`
      with: `getMemory(snapshotId)`, `upsertMemory(snapshotId, payload)`,
      `isMemoryStale(snapshotId)` (compares against
      `repo_snapshots.updated_at`), and re-exports under
      `packages/db/src/learning-memories/index.ts`.
- [ ] `packages/db` `exports` map updated to expose
      `./learning-memories` (mirrors the `./learning-units` and
      `./mapper` entries).
- [ ] Unit tests cover: insert, read-by-snapshot, upsert (idempotent on
      same `snapshot_id`), cascade delete on snapshot removal, and
      stale-detection true/false cases.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm build`, `pnpm test` pass.

## Technical Details

- Mirror the column-shape decisions used in M6 `project_maps`, M7
  `learning_units`, M8 `diff_reviews`, M9 `challenges` — JSON text columns
  for structured payloads, epoch integers for timestamps, FK with cascade
  delete from `repo_snapshots`.
- Use `.unique()` on `snapshot_id` so the row is at most one per
  imported repo (FR-1, FR-5).
- The DAL must not import any LLM client. It is read/write only.
  Synthesis lives in tasks 4 / 5 / 6.
- Keep TS interfaces strict — every JSON-column field declared, no
  `Record<string, unknown>` escape hatches.

## Dependencies

None in-epic. Reads from `repo_snapshots` (M11, shipped).
