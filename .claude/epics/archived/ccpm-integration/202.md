# Task: Teaching layer (deterministic, parameterized)

## Description

Create `packages/db/src/ccpm/teaching.ts` — pure, deterministic explanations of
each artifact type and the overall spec-driven flow, **parameterized by the real
map** (e.g. "this epic decomposed into N tasks, M of which ran in parallel; K are
closed"). No LLM (AD-3): templated copy filled from the graph (004), so US-2's
"references the actual artifact" holds without an SDK call or integrity-check
surface. Also supplies the educational copy for the `NoCcpmWorkflow` degradation
state (what CCPM is, why it matters, link to the M2 Golden Path).

## Acceptance Criteria
- [ ] Per-artifact explanations (PRD, epic, task, issue/PR link) each return
      beginner-first copy that names the artifact's purpose AND its place in the
      spec-driven flow.
- [ ] Explanations are parameterized by the actual map (counts, parallelism,
      status) — not static boilerplate; verified by a test asserting real numbers
      appear in the output.
- [ ] Copy names the professional value (traceability, bounded work, reviewable
      scope) a hiring manager cares about.
- [ ] Degradation copy explains what CCPM is and why it's valuable, and carries a
      reference to the "Agentic CCPM Workflow" Golden Path (M2) for the UI to link.
- [ ] No raw HTTP codes / jargon-without-definition; deterministic and pure.
- [ ] Vitest covers a populated map, an unsynced-task case, and the degradation copy.

## Technical Details
- New file only: `packages/db/src/ccpm/teaching.ts` (+ `teaching.test.ts`).
- Input is the `CcpmTraceabilityMap` / `NoCcpmWorkflow` type from 004; output is
  a typed explanation structure the UI renders (no markdown strings baked with
  app concerns).
- Keep copy in one place (a small templating table) so it's reviewable and
  testable; no Anthropic SDK import.
