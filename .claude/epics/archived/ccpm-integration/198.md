# Task: Generalized CCPM parser (PRD + epic + task)

## Description

Create `packages/db/src/ccpm/parse.ts` — pure parsers that turn CCPM artifact
file contents into typed structures: **PRDs** (`.claude/prds/*.md`), **epics**
(`.claude/epics/<e>/epic.md`), and **tasks** (`.claude/epics/<e>/<N>.md`),
**including the `archived/` subtree** (which M7's task adapter intentionally
excludes). Generalizes the frontmatter approach already proven in
`ccpm-task-adapter.ts` (`parseCcpmTaskFile`) rather than duplicating it.

## Acceptance Criteria
- [ ] PRD parser extracts `name`, `description`, `status`, `created` + body.
- [ ] Epic parser extracts `name`, `status`, `progress`, `prd`, `github` + body.
- [ ] Task parser extracts `name`, `status`, `github`, `depends_on`, and the
      optional `parallel` / `conflicts_with` + body.
- [ ] Path classifiers identify each artifact type from a repo-relative path,
      including under `.claude/epics/archived/<e>/...`.
- [ ] Tolerant of missing optional fields and of a frontmatter-less file
      (returns body-only, never throws) — same clean-miss discipline as M7.
- [ ] Pure and total; exported for direct unit testing. Vitest covers each
      artifact type, the archived path, quoted/unquoted scalars, and
      `depends_on` list parsing.

## Technical Details
- New file only: `packages/db/src/ccpm/parse.ts` (+ `parse.test.ts`). No edits to
  M7's `ccpm-task-adapter.ts` — leave the learning-workspace path untouched.
- Reuse the frontmatter-splitting technique from `parseCcpmTaskFile`
  (delimiter/field regexes, `unwrapScalar`, `parseDependsOn`); factor shared
  helpers locally rather than importing across module boundaries if it keeps the
  two modules decoupled.
- Output types should be graph-friendly (stable refs: PRD by name, epic by name
  + `prd` link, task by `epic/<name>/<id>` like M7's `taskRef`, including an
  `archived: boolean` flag on epic/task).
- No network, no live filesystem — parsers take raw `content: string`.
