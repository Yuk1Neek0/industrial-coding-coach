# Task: Implement snapshot file viewer route

## Description

Implement the read-only Snapshot File Viewer per the Page Spec from #266:
`/repos/[owner]/[repo]/files` rendering the stored file tree and captured
key-file contents, with the `?path=` deep-link contract the wiring tasks
(#269, #270) will consume. Closes the M11 "snapshot-view route" deferral.

## Acceptance Criteria

- [ ] Route implemented per `docs/design/snapshot-file-viewer.page-spec.md`
      (URL contract, layout, header, tree, file pane).
- [ ] Three file states per spec: captured → contents in plain monospace
      `<pre>` (no syntax-highlighting dependency); in-tree-not-captured →
      explicit "content not captured at import" + metadata; unknown path →
      not-found handling (no 500).
- [ ] Unknown owner/repo → `not-found.tsx` consistent with sibling repos
      pages; `loading.tsx`/`error.tsx` present.
- [ ] Data via `getImportedRepo`/`getRepoTree`/`listRepoFiles`/`getRepoFile`
      only — zero network calls, no DAL changes unless a real read-only gap
      appears (AD-1; if one does, add the minimal function + test in
      `packages/db/src/github/repos.ts` style).
- [ ] Shared `AppNav` (`active="repos"`); repos feature styling conventions.
- [ ] `pnpm lint` / `typecheck` / web `build` pass.

## Technical Details

- Server Component page keyed off `searchParams` for `?path=`; tree pane can
  be a Client island only if the spec's collapsing interaction needs it —
  prefer server-rendered simplicity.
- Tree source is `repo_snapshots.fileTree` via `getRepoTree`; captured set
  via `listRepoFiles` (paths) — distinguish key files in the tree per spec.
- Big trees: follow the spec's grouping/cap decision; no virtualization, no
  tree library.
