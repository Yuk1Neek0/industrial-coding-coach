# Task: Page Spec — Snapshot File Viewer

## Description

Write the Page Spec for the snapshot file viewer (US-2): the read-only page
that renders an imported snapshot's file tree and captured key-file
contents, closing the M11 "snapshot-view route" deferral. The implementation
task (#268) builds directly from this spec (AD-2), and the wiring tasks
(#269, #270) consume the URL contract this spec fixes.

## Acceptance Criteria

- [ ] `docs/design/snapshot-file-viewer.page-spec.md` exists, following the
      structure of recent specs: purpose, route + URL contract, data
      sources, layout, states, interactions, a11y notes.
- [ ] Fixes the URL contract: route `/repos/[owner]/[repo]/files` with
      `?path=<repo-relative path>` selecting a file (AD-3) — or documents a
      deliberate override; the contract must support deep links from other
      features.
- [ ] Specifies data sources: `getImportedRepo` (snapshot identity),
      `getRepoTree` (full tree from `repo_snapshots.fileTree`),
      `listRepoFiles`/`getRepoFile` (captured key-file contents).
- [ ] Specifies the three file states: captured (render contents, plain
      monospace `<pre>`, no syntax highlighting), in-tree-but-not-captured
      ("content not captured at import" + tree metadata + which categories
      get captured), path-not-in-tree (not-found state, no 500).
- [ ] Specifies tree rendering (directories collapsible or grouped — keep it
      simple, no tree library), captured-file affordance (key files visually
      distinguished), and the no-file-selected default state.
- [ ] Specifies header (owner/repo, ref badge, imported time, back link to
      `/repos`), shared `AppNav` (`active="repos"`), and repos feature
      styling conventions.

## Technical Details

- Read `packages/db/src/github/repos.ts` (tree entry shape, file row shape)
  and `packages/db/src/github/key-files.ts` (what gets captured and why)
  before writing — the spec's honesty about "not captured" depends on it.
- Trees can be thousands of entries; spec a pragmatic cap/grouping (e.g.
  collapse by top-level directory) rather than virtualization.

## Dependencies

None (Wave 1). #268/#269/#270 depend on the URL contract fixed here.
