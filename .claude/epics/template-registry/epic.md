# Epic: template-registry

## Overview

Build the Template Registry MVP (Milestone 3): a `templates` table in the
existing catalog SQLite database, a typed data-access layer, 15 seeded template
entries, referential integrity with the M2 catalog, and a Template Registry UI
page. This makes every `templatesReferenced` slug in the M2 catalog resolve to a
real, explained entry.

## Architecture Decisions

- **Storage:** reuse the M2 catalog SQLite database (ADR 0006) — add one
  `templates` table via Drizzle, no new database.
- **Schema (MVP):** one `templates` table; list-valued fields (risks,
  alternatives, sources, fit factors) as JSON columns — same pattern as
  `golden_paths`.
- **Fit data, not a fit engine:** templates store structured fit data; the
  algorithm that scores them against a user is M4, out of scope here.
- **Registry UI:** built via the **v0 round-trip** — page spec + v0 prompt
  authored here, generated by the user in v0, then integrated.
- **No LLM** in M3 — template entries are written and reviewed by hand.
- A template-schema ADR is created during this epic only if the schema proves
  non-trivial ("ADR if needed").

## Technical Approach

### Frontend Components

- A **Template Registry page** in `apps/web` — list view (all 15, browsable by
  category), detail view (one template, including its fit data). Built from a
  page spec via v0, using `packages/ui` (shadcn/ui). Mirrors the M2 Catalog
  page structure.

### Backend Services

- Drizzle `templates` schema + migration in `packages/db`; a typed data-access
  module: list all, get by slug, list by category, and resolve a Golden Path's
  `templatesReferenced` into full entries. No separate server process.

### Infrastructure

- A version-controlled **seed script** loading the 15 template entries,
  alongside the existing Golden Path seed. A referential-integrity test asserts
  every `templatesReferenced` slug in `goldenPathSeed` resolves to a template.

## Implementation Strategy

001 adds the schema + migration (foundational). 002 (data-access layer) and 003
(15 entries + seed) then run in parallel. 004 (the Registry page spec + v0
prompt) can be written from the PRD at any time and ends in a **hand-off to the
user**. 005 integrates the v0 output last.

- 003 — Author 15 template entries + seed script + referential-integrity test

- 005 — Integrate the Template Registry UI page

## Dependencies

- M2 golden-path-catalog (complete) — provides the SQLite DB, Drizzle setup,
  and the `templatesReferenced` slugs to resolve.
- ADR 0006 (storage); ADR 0008 (runs in parallel with M11).
- 002→001; 003→001; 005→002,004.
- 005 also depends on the **v0 output** the user generates from task 004.

## Success Criteria (Technical)

- `templates` table created reproducibly via migration; seed loads 15 entries.
- Data-access layer typed and tested (list all, get by slug, by category,
  resolve references).
- Referential-integrity test passes — every `templatesReferenced` slug resolves.
- Template Registry page lists all 15, supports category browsing, shows full
  detail incl. fit for each.
- Every entry has what-it-generates, why-used, fit data, risks, alternatives,
  learning notes, and sources populated.
- `pnpm lint`, `pnpm typecheck`, `pnpm build` pass; CI green.
