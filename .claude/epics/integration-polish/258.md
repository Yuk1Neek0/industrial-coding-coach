# Task: GitHub client listPullRequests with bounded pagination

## Description

The M11 GitHub client (`packages/db/src/github/client.ts`) has
`getPullRequest`/`getPullRequestFiles` but no way to list a repo's pull
requests, which is why the M8 reviews flow makes the user type a PR number.
Add `listPullRequests` with the same typed-error and bounded-pagination
shape as the existing methods. Follow-up named in the M8 and M9
retrospectives.

## Acceptance Criteria

- [ ] `listPullRequests(ref, options?)` added to the client interface and
      implementation, calling `GET /repos/{owner}/{repo}/pulls`.
- [ ] Returns a typed result with per-PR `{ number, title, state, updatedAt }`
      (extend only if the picker needs it), plus a `truncated` flag.
- [ ] Bounded pagination: same pattern as `getPullRequestFiles` (paginate
      until a short page, hard cap with `truncated: true`); default cap
      consistent with existing `DEFAULT_MAX_*` constants.
- [ ] Options support `state: "open" | "closed" | "all"` (default `"open"`).
- [ ] Typed errors consistent with existing methods (`not_found`,
      `rate_limited`, etc.) — no thrown exceptions for expected failures.
- [ ] Tests in `packages/db/src/github/pull-requests.test.ts` style: happy
      path, 404 → typed `not_found`, pagination until short page, cap +
      truncated flag.
- [ ] Existing mock client objects in tests that enumerate client methods are
      updated to include the new method (e.g. `import.test.ts`,
      `repos.test.ts`, `ccpm/*.test.ts` mocks).
- [ ] `@workspace/db` tests green; `pnpm lint` / `typecheck` pass.

## Technical Details

- Mirror `getPullRequestFiles` (client.ts ~line 654) for pagination shape and
  `getPullRequest` (~line 645) for error mapping.
- Read-only on the already-granted scope; no auth changes.
- Keep the method on the same client interface (client.ts ~line 361 region).
