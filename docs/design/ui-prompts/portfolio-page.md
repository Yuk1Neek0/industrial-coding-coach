## Prompt — paste into Claude Design

Build a **Portfolio Page** for a learning-coach web app, using Next.js
(App Router), React, TypeScript, Tailwind CSS, and shadcn/ui. It is a
**single page** at route `/portfolio/[owner]/[repo]`. Light and dark
mode. Use only mock sample data — do not add data fetching, API calls,
or a database; render from a typed in-file object so it is trivial to
swap for real server data later.

**Critical: produce a single page.** This page composes five artifact
sections in a fixed order on **one** scrollable route with anchor
links. **Do not split it into sub-routes** (no
`/portfolio/.../architecture`, no `/portfolio/.../qa`, no
`/portfolio/.../resume`, etc.). The shareable share-with-an-interviewer
affordance is "send the URL" and that URL is the *one* portfolio route.

### Domain

The app coaches a job-seeking junior developer to genuinely understand
projects they built with heavy AI assistance. The user has imported one
of their GitHub repositories and worked through five prior milestones
on it: a stack explainer (M5), a project logic map (M6), per-issue
learning units (M7), AI-diff reviews (M8), and project-tied debug /
expansion challenges (M9). This page is the **culmination** of that
work: it composes the user's **learning memory** for the repository
into a single shareable view — the Architecture Explanation they can
speak from, the Learning Memory Tree of what they now understand (and
what they still need to revisit), the Interview Q&A they can practice
with, the Résumé Bullets they can paste, and the Debug Stories they
can talk about.

Two of the five artifacts are generated by bounded Anthropic SDK calls
(Interview Q&A, Résumé Bullets); three are composed deterministically
from the M5–M9 rows (Architecture Explanation, Learning Memory Tree,
Debug Stories). **All five are cached in a single `learning_memories`
row.** **The page reads the cache; it never calls the SDK on render.**
The only path that touches the SDK is the explicit "Regenerate memory"
action in the header.

The page is honest that the AI-generated artifacts are AI-generated —
the header carries a small "AI-generated Q&A and résumé bullets,
grounded in your repo" label. Copy is plain, calm, encouraging,
jargon-light.

**Honest output is the contract.** The Learning Memory Tree includes a
"Still to revisit" branch surfacing the user's weak-area entries from
M7/M8/M9 grading — this branch is **always visible when populated,
never collapsed by default, never softened**. Showing the user what
they don't know yet is on-thesis with the product's
"comprehension-over-completion" rule.

### Typed shapes — render from these (paste into the mock data)

The page renders one **`LearningMemory`** object plus a `repo` /
`ref` identifier and a `isStale` boolean (the stale-data banner
trigger). The typed shapes:

  snapshotId: number;
  architectureExplanation: ArchitectureExplanation;
  learningMemoryTree: LearningMemoryTree;
  interviewQa: InterviewQA[];
  resumeBullets: ResumeBullet[];

  generatedAt: string;

}

interface LearningMemoryLeaf {

interface LearningMemoryRevisitEntry {
  area: string;
  explanation: string;
  suggestion: string;
  fileRefs: string[];    // real project-map paths
  source: {
    kind: "learning-unit" | "diff-review" | "challenge-attempt";

    label: string;

}

interface InterviewQA {

  answer: string;

    | "issue-learning"
    | "diff-risk"

interface ResumeBullet {
  id: string;
  text: string;          // ≤ 160 characters, "verb + outcome + technology" shape
  citedFiles: string[];
  citedStack: string[];
}

interface DebugStory {
  challengeId: number;
  challengeType: string;       // human-readable label, e.g. "Add a loading or error state"
  taskSummary: string;

interface PortfolioPageData {

  `/reviews/r/r_abc123`,
  `/repos/mia-dev/portfolio-api/challenges/c_xyz789`).
- **`learningMemoryTree.stillToRevisit`** — **2–3 entries** (this is

- **`interviewQa`** — **5 entries** covering all five `groundArea`s

- **`resumeBullets`** — **4 bullets**. Each ≤ 160 characters,

- `generatedAt` — 4 days ago, so the stale banner has a real reason

Use plausible content — no "lorem ipsum".

### Page layout — route `/portfolio/[owner]/[repo]`

A single readable column (comfortable max width). From top to bottom:

1. A **page header**: `{owner}/{name}` as an `<h1>`; the `ref` as a
   `Badge` next to it; a one-line description: "Your learning memory
   and portfolio artifacts for this repository."; and a small,
   honest **"AI-generated Q&A and résumé bullets, grounded in your
   repo"** badge/label (real text, calm styling — not icon-only).
2. To the right of the header on wide screens (stacked below on
   mobile), a **top-level actions bar** with three buttons in this
   order:
   - **Regenerate memory** — a primary `<button>`. On a memory that
     already has Q&A or résumé bullets, click opens a real
     `AlertDialog` ("Regenerate your learning memory? Your existing
     cached artifacts will be replaced; M5–M9 rows are not
     affected.") before invoking. On a first-open (no row yet),
     click invokes directly without a dialog. The button has a
     visible in-progress state (spinner, disabled, accessible
     "Regenerating your learning memory…" status); failure shows a
     quiet inline error next to the button (one of: *"Set
     `ANTHROPIC_API_KEY` in your `.env` to regenerate."*, *"Couldn't
     ground the new artifacts against your repo. Try regenerating."*,
     or *"Couldn't regenerate. Try again."*).
   - **Export bundle (.zip)** — a secondary `<button>`. In-progress
     spinner; failure inline. Disabled when `memory` is `null`.
   - **Export PDF** — a secondary `<button>`. In-progress spinner;
     failure inline. Disabled when `memory` is `null`.
3. A **stale-data banner** (calm `Alert`-shape) shown **only when**
   `isStale === true`. Heading "Your learning memory may be out of
   date." Body: *"This repository's snapshot was updated after this
   memory was last generated. Click **Regenerate memory** to refresh
   the artifacts from your latest M5–M9 outputs."* Includes a
   secondary inline **Regenerate memory** button. Convey meaning by
   the heading text + an `info`/`clock` lucide icon — never by red
   alone.
4. A compact **in-page anchor nav** under the banner (or under the
   header if no banner): a horizontal `<nav>` of five anchor links
   in fixed order — **Architecture**, **Memory tree**,
   **Interview Q&A**, **Résumé bullets**, **Debug stories** — each
   `href="#<slug>"`. The slugs are exactly:
   `#architecture`, `#memory-tree`, `#interview-qa`,
   `#resume-bullets`, `#debug-stories`. The nav is **sticky** on
   wide screens, **non-sticky** on mobile. Labelled
   `<nav aria-label="In-page sections">`.
5. The **five artifact sections, in this fixed order** — each is a
   real `<section id="<slug>">` with the slug from the nav, and a
   clearly-headed `<h2>`:
   a. **Architecture Explanation** (`id="architecture"`).
   b. **Learning Memory Tree** (`id="memory-tree"`).
   c. **Interview Q&A** (`id="interview-qa"`).
   d. **Résumé Bullets** (`id="resume-bullets"`).
   e. **Debug Stories** (`id="debug-stories"`).
6. A quiet **footnote** below the last section: "Cached per
   imported repository. Click *Regenerate memory* to refresh after
   working through more of M5–M9." Informational, not a link.

**Do not reorder these five sections. Do not add a sixth section.
Do not introduce per-artifact sub-routes. The fixed order matches
the markdown bundle's `portfolio.md` and the PDF — all three reading
surfaces are byte-aligned for the user.**

#### Section a — Architecture Explanation (`#architecture`)

`<h2>` "Architecture Explanation". A short intro line under the
heading: *"Composed deterministically from your stack explainer and
project map — no LLM call, never hallucinates against your data."*

Then, in order: render `intro` as a single prose paragraph; then
each of `stackSection`, `architectureSection`, `keyFlowsSection`
as their own labelled `<h3>` block using `section.heading`. Inside
each: render `section.paragraphs` as readable prose, generous
spacing; then `section.citedFiles` as a wrapped row of monospace
path chips (each chip a `Badge` of `<code>{path}</code>`); then
`section.citedStack` as a wrapped row of calm-shaped chips with
the stack technology name.

#### Section b — Learning Memory Tree (`#memory-tree`)

`<h2>` "Learning Memory Tree". A short intro: *"Things you now
understand about this repo, and the M7 / M8 / M9 row that taught
each one."*

Then render `branches` as a vertical list. Each branch:
`<h3>` matching `branches[].heading`; under it a `<ul>` of leaves.
Each leaf is one `<li>`: the `concept` as the entry title; the
optional `filePath` as a monospace path chip when present; a small
"Learned in **{label}** →" link to `source.href` (a real `<a>`,
keyboard-operable).

Then **"Still to revisit"** as a clearly distinct sub-section —
`<h3>` "Still to revisit", with a short framing line: *"Weak-area
entries from your M7 / M8 / M9 grading. These are what you should
brush up on before an interview."*

Render `stillToRevisit` as a `<ul>` of `Card`-shaped blocks
(`Card` / `CardHeader` / `CardContent`). Each block:

- `area` as `<h4>` heading;
- `explanation` + `suggestion` as readable prose, generous spacing;
- `fileRefs` as a row of monospace path chips;
- a "Surfaced from **{source.label}** →" link to `source.href`.

**Render this sub-section in full when populated. Do not collapse
it by default. Do not hide individual entries.** This is the
honest-output centerpiece of the page (PRD FR-4). Showing the user
what they don't know yet is the point.

#### Section c — Interview Q&A (`#interview-qa`)

`<h2>` "Interview Q&A". A short intro: *"Generated by a bounded
Anthropic SDK call from your M5/M6/M7/M8/M9 rows; every answer cites
a real file path or stack entry from your repo."*

Render `interviewQa` as a vertical list of expanded entries —
`Accordion` items kept **expanded by default** (or `Card`s; either
shape works as long as the user can scan-read every entry without
clicking). Each entry:

- `question` as `<h3>`;
- `answer` as readable prose;
- a small `Badge` for `groundArea` with the human-readable label
  ("Stack" / "Architecture" / "Issue learning" / "Diff & risk" /
  "Debug & expansion");
- a "grounded in" row of monospace path chips (`citedFiles`) and
  calm stack chips (`citedStack`) at the bottom of the entry.

#### Section d — Résumé Bullets (`#resume-bullets`)

`<h2>` "Résumé Bullets". A short intro: *"Generated by a bounded
Anthropic SDK call; ≤ 160 characters each, in industry-standard
verb + outcome + technology form. Select and copy any bullet, or
grab the full set in the markdown bundle."*

Render `resumeBullets` as a real `<ul>` of bullets. Each bullet:

- `text` as the primary body of the `<li>` — selectable, plain
  prose, no `<button>` wrapper;
- a quiet "grounded in" sub-line of monospace path chips
  (`citedFiles`) and stack chips (`citedStack`) under the text.

**Do not add a copy-to-clipboard button per bullet** — that is
explicitly out of scope. The user copies from the rendered text or
from the exported `resume-bullets.md`.

#### Section e — Debug Stories (`#debug-stories`)

`<h2>` "Debug Stories". A short intro: *"Composed deterministically
from your M9 challenge attempts — what you tried, what you scored,
and the feedback the grader gave."*

Render `debugStories` as a vertical list of `Card`s, one per story.
Each card:

- `challengeType` as `CardTitle`;
- `taskSummary` as `CardDescription`;
- `explanationExcerpt` as a calm pull-quote-shaped block inside
  `CardContent`;
- `gradingResult.score` + `gradingResult.scoreLabel` as a compact
  "{score} / 100 · {scoreLabel}" status line (text, never color
  alone); `gradingResult.summary` as a single feedback sentence
  under it;
- `attemptedAt` as a muted "Attempted {attemptedAt}" line;
- a "View this challenge →" link to `href` (back to the M9
  Challenge Detail page).

### States — design all of these

Provide simple toggles or separate preview screens so all of these
can be viewed:

- **Populated, fresh** — `memory` populated, `isStale: false`. The
  banner is absent; the anchor nav and all five sections render.
- **Populated, stale** — `memory` populated, `isStale: true`. The
  banner sits above the anchor nav with the normative copy and an
  inline Regenerate button. The cached sections still render —
  staleness labels them, it does not hide them.
- **First-open empty (no memory yet)** — `memory: null`. The
  anchor nav and the five artifact sections are **absent**. The
  main content area shows a calm full-page panel: heading "No
  learning memory yet for this repository", a short explanation
  that M10 caches artifacts on first generation, and a primary
  **Generate memory** button. The header (title, actions bar with
  Export buttons disabled, AI-generated label) stays visible.
- **Per-section empty** — `memory` populated but one section's
  array is empty (e.g. `interviewQa.length === 0`). Render that
  section's `<h2>` plus an inline "Not yet — click *Regenerate
  memory* in the header to populate this" (for Q&A / Résumé
  Bullets) or "Not yet — work through some M9 challenges to
  populate your debug stories" (for Debug Stories) note. Do not
  hide the section silently — its slug is still in the anchor nav.
- **Loading** — a skeleton view (shadcn `Skeleton`): a header bar,
  a banner-sized placeholder, an anchor-nav placeholder (five
  chip-sized blocks), and five `<section>` placeholders matching
  the five artifact sections — each with an `<h2>`-shaped block
  and a few prose-paragraph + chip placeholders. The page never
  shows an LLM-in-progress spinner on initial render — only the
  Regenerate button does (and only when the user clicks it).
- **Error — repo not imported** — full-page panel: heading
  "This repository isn't imported yet.", a short line, and an
  "Import this repository" link to `/import`. No stack traces.
- **Error — load failed** — full-page error block: heading
  "Couldn't load your learning memory", a short explanation, and
  a "Try again" button. No stack traces.
- **Regenerate — in progress** — the button shows a spinner and
  is disabled; the rest of the page remains visible and
  read-only. The user can keep reading the previous cached
  version.
- **Regenerate — missing API key** — a quiet inline error sits
  next to the button: *"Set `ANTHROPIC_API_KEY` in your `.env`
  to regenerate."* The page itself stays readable.
- **Regenerate — integrity failure** — a quiet inline error
  sits next to the button: *"Couldn't ground the new artifacts
  against your repo. Try regenerating; if it keeps failing, your
  project map or stack explainer may need a refresh."* The
  previous cached row is retained.
- **Export bundle / Export PDF — in progress / failed** — a
  spinner on the button; failure surfaces an inline error next
  to the export button.

### Visual & accessibility requirements

- Clean, modern, content-first design. Generous spacing, readable
  typography, calm and trustworthy — a learning tool, not a
  marketing page. Match the visual language of the M6 Project Map,
  M7 Issue Learning Workspace, M8 Diff Review, and M9 Challenge
  Detail / List pages so the milestones read as one product.
- Fully responsive: comfortable on mobile and desktop. The
  actions bar stacks under the title on mobile; the anchor nav
  becomes non-sticky on mobile; the artifact sections each render
  comfortably in a single column.
- Light and dark mode, using shadcn/Tailwind theme tokens (no
  hard-coded colors).
- Use **lucide-react** icons (e.g. `clock` / `info` for the stale
  banner; `refresh-cw` for Regenerate; `download` for Export;
  `file-text` for the PDF; `arrow-up-right` for back-links;
  `book-open-text` for Learning Memory; `messages-square` for Q&A;
  `file-output` for Résumé Bullets; `bug` for Debug Stories;
  `layers` for Architecture).
- Semantic HTML: exactly one `<h1>` per page (the `owner/repo`
  title); section headings descend in order (`<h2>` for each of
  the five artifact sections, `<h3>` inside Architecture / Memory
  Tree / Q&A as specified, `<h4>` for the revisit-entry `area`
  inside Memory Tree); no skipped levels. Use `<main>`, `<nav>`,
  and `<section>` landmarks. The anchor nav is a labelled `<nav>`
  containing a `<ul>` of `<li>`s with anchor links.
- **Anchor nav.** Activating a link scrolls to the matching
  `<section id>` and focuses its `<h2>` (`tabIndex={-1}`). The nav
  links carry their full text labels (no icon-only triggers).
- **Stale-data banner.** A real text region (not color-only) with
  `role="status"` or `aria-live="polite"` so assistive tech
  announces it on appearance. The icon is decorative
  (`aria-hidden`).
- **Top-level actions.** The three buttons are real `<button>`
  elements with clear accessible names. The Regenerate
  confirmation dialog is a real `AlertDialog` with focus trap and
  Esc-to-dismiss. The in-progress state uses `aria-busy="true"`
  and a status reading "Regenerating your learning memory…" /
  "Building your bundle…" / "Building your PDF…". Inline errors
  are announced via an `aria-live="polite"` region next to each
  button.
- **Memory tree "Still to revisit".** Each revisit entry is a real
  `<article>` (or `<section>`) with its `area` as an `<h4>`. The
  sub-section is **never** collapsed by default and individual
  entries are never hidden — a screen reader reads them inline.
- **Path chips & stack chips.** File paths are `<code>` inside the
  chip; each chip's accessible name names the path. Stack chips
  name the technology. Long lists wrap — nothing meaningful is
  hidden behind hover.
- **AI-generated label.** Real, announced text — not color-only or
  icon-only.
- **Keyboard.** Full keyboard operability in logical order: anchor
  nav links → Regenerate / Export buttons → confirmation dialog
  controls → each section's interactive elements (source
  back-links, Debug-Story "View this challenge →" links). Enter /
  Space activate. Visible focus ring throughout. DOM order =
  visual order.
- **Color & contrast.** WCAG 2.1 AA in light and dark themes
  (`next-themes`). The `ref` badge, the AI-generated label, the
  stale banner, the ground-area badges, and the score line on
  Debug Stories convey meaning by text + icon, not color alone.
- **Targets.** Interactive targets (anchor links, action buttons,
  source back-links, dialog controls) are comfortably sized for
  pointer and touch.

### Components to use

shadcn/ui: `Card` (`CardHeader`, `CardTitle`, `CardDescription`,
`CardContent`), `Badge`, `Button`, `AlertDialog`, `Alert`

composable so they integrate cleanly into an existing shadcn/ui
